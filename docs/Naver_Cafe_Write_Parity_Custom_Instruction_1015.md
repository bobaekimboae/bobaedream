이 내용만 기준으로 작업한다. 먼저 네이버 카페 글쓰기 UI를 독립 테스트 화면에 1:1로 재현하고, 픽셀 검수가 통과한 뒤에만 보배드림 커스텀 작업을 별도 작업으로 시작한다. 두 단계를 한 브랜치나 한 PR에 섞지 않는다.

# 작업 A — 네이버 카페 글쓰기 UI 1:1 재현

3. 기존 변경이 없는 깨끗한 worktree와 전용 브랜치를 만든다.
4. 아래 파일의 현 구조를 읽고 재사용 가능 부분을 표로 보고한다.
   - `public/community/bobaedream-pc-board-list.html`
   - `public/community/bobaedream-pc-interactions.js`

5. 기존 글쓰기 구현은 게시판 선택·제목·textarea·태그·등록과 `localStorage` 저장만 제공한다. 이 코드를 바로 확장하지 말고 우선 독립 테스트 화면을 만든다.

## [2/8 · 약 25%] 원본 화면 캡처와 실측

네이버 카페 로그인 상태의 실제 글쓰기 화면을 크롬에서 열되 입력·업로드·등록은 하지 않는다.

### 필수 뷰포트

- PC 기준: 1536×864
- 모바일 기준: 384×844
- 반응형 확인: 360×800, 412×915

### 필수 상태 캡처

1. 빈 글쓰기 기본 화면
2. 게시판 선택 모달 열림
3. 게시판 검색 결과
4. 게시판 선택 완료 상태
5. 텍스트 도구막대 닫힘·열림
6. 상세설정 닫힘·열림
7. 임시글 목록
8. 필수값 미입력 등록 시 검증 상태
9. 이탈 확인 상태
10. 사진 첨부 직전 화면과 업로드 UI 구조

### 상태별 실측 항목

- 뷰포트, 전체 콘텐츠 폭, 좌우 여백
- 상단바 높이와 고정 여부
- 모든 행의 x/y/width/height
- 제목·본문·태그의 시작점과 높이
- 아이콘 슬롯, 실제 SVG 표시 크기, 아이콘 간격
- 글꼴 family/size/weight/line-height/letter-spacing
- 색상, 테두리, 배경, radius, shadow
- 모달 폭·높이·스크롤 영역·검색창·라디오 위치
- 버튼 활성·비활성·hover·focus 상태

육안 추정으로 CSS 값을 정하지 않는다. 브라우저의 `getBoundingClientRect()`와 computed style 결과를 JSON으로 저장한다.

개인정보가 보이는 캡처는 저장하지 않는다. 원본 캡처는 공개 경로에 두지 않고 테스트 산출물로만 보관한다.

## [3/8 · 약 37%] 노션 아이콘 확보·매핑

노션 DB 전체를 공용 아이콘 원천으로 사용한다. 먼저 다음 글쓰기 관련 카테고리를 조회하되, 필요한 아이콘이 없거나 더 정확한 자산이 다른 카테고리에 있으면 같은 DB의 다른 아이콘도 검색해 사용한다.

- `N_글쓰기`
- `N_미디어 업로드`
- `네이버 카페 PC웹 아이콘`
- `네이버 모바일웹 아이콘`
- `네이버 카페 셰브론/화살표`
- `네이버 카페 영상 아이콘`

### 같은 DB의 다른 아이콘 사용 규칙

- 위 카테고리만으로 범위를 제한하지 않는다. DB의 `이름`, `명칭`, `명칭(영어)`, `아이콘명`, `카테고리`, `태그 (형태)`, `UI`, `위치` 필드를 함께 검색한다.
- 검색·닫기·설정·더보기·삭제·수정·체크·라디오·스위치·업로드·재정렬·알림·사용자 등 필요한 기능은 DB 전체에서 가장 정확한 아이콘을 고른다.
- 선택 우선순위는 `화면 출처가 같은 아이콘` → `기능명이 정확히 같은 아이콘` → `형태와 선 굵기가 같은 아이콘` 순서다.
- 동일 기능의 후보가 여러 개면 원본 화면과 나란히 비교한 후보표를 만들고 가장 가까운 한 개만 사용한다.
- 글쓰기 카테고리에 없는 아이콘을 사용한 경우 manifest의 `sourceCategory`와 `selectionReason`에 출처와 선택 이유를 기록한다.
- 같은 DB 안에서도 차량·필터 등 문맥이 전혀 다른 아이콘은 이름만 같다는 이유로 사용하지 않는다.
- 노션 DB에 적절한 아이콘이 실제로 있는데 외부 라이브러리나 새 SVG로 대체하면 검수 실패다.

### 우선 매핑 대상

- 닫기, 셰브론, 체크마크, 맨 위로
- 사진, 동영상, 링크, 파일, 장소
- 굵게, 기울임꼴, 취소선, 위 첨자, 제목
- 글머리 기호, 숫자 목록, 인용 블록, 코드 블록, 표
- 태그 추가
- 임시저장본 수정·삭제
- 이미지 추가·사진 더 추가·사진 수정

### 아이콘 규칙

- 이모지, 유니코드 기호, CSS 그림, 새로 그린 SVG, 외부 아이콘 라이브러리로 대체하지 않는다.
- 원본 SVG의 viewBox와 path를 수정하지 않는다.
- 파일명을 서비스 용도에 맞게 정규화하고 `icon-manifest.json`을 작성한다.
- manifest 필드: `usage`, `sourceCategory`, `selectionReason`, `notionPageUrl`, `notionFileId`, `originalName`, `localFile`, `sha256`.
- 이름 없는 행이나 용도를 판단할 수 없는 아이콘은 사용하지 말고 `🟡 매핑 필요`로 보고한다.
- 필요한 아이콘이 노션에 없으면 임의 대체하지 말고 `🔴`로 멈춘다.

## [6/8 · 약 75%] 시안 데이터와 발행 흐름

## B2. 변경 허용 범위

- 네이버 계열 녹색 → 보배드림 브랜드 컬러 토큰
- 네이버 용어 → 보배드림 게시판 용어
- 게시판 목록 → 보배드림 커뮤니티 게시판 데이터
- 사용자 프로필 → 보배드림 로그인 사용자
- 테스트 저장소 → 보배드림 게시글·임시글 API
- 공개·검색·공유 설정 → 보배드림 운영 정책
- 노션 아이콘은 그대로 사용하되 색상은 승인된 토큰 범위에서만 조정

## B3. 실제 서비스 연결

- 게시글, 본문 블록, 첨부, 태그, 임시글, 게시판 권한을 명시적 스키마로 분리한다.
- 업로드는 presigned URL 방식으로 파일 저장소에 직접 전송하고 진행률·실패 재시도를 제공한다.
- 서버에서 MIME·확장자·용량 검증, 이미지 재인코딩, 악성 파일 검사, HTML sanitize를 수행한다.
- 게시글 등록은 트랜잭션과 idempotency key를 사용한다.
- 게시판 쓰기 권한, 차단 사용자, 도배 제한, 금칙어, 신고·관리 로그를 연결한다.
- 운영 DB와 운영 저장소 반영은 별도 승인 전까지 금지한다.

## B4. 커스텀 완료 검증

- 작업 A와 구조 비교에서 승인되지 않은 위치·크기 변화 0건
- 목록형 게시판 → 글쓰기 → 임시저장 → 복원 → 등록 → 상세 → 목록 복귀 전체 흐름 통과
- PC·모바일 접근성: 라벨, 포커스 순서, 키보드, 명도 대비 확인
- 실패 상태: 네트워크 오류, 업로드 실패, 권한 없음, 중복 등록, 세션 만료 확인
- 별도 PR을 생성하고 사용자 승인 전에는 병합·배포하지 않는다.
