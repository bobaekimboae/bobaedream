# 매물 링크 가져오기 (listing-import) 제품 명세 v1

작성: 2026-11-23 · 상태: 상용 1차(서버·작업기 완성, 화면 연결 전)

## 1. 한 줄 요약
딜러가 다른 사이트에 올린 **자기 매물 링크**를 붙여 넣으면, 사진·차량 정보·판매자 정보를 가져와 보배드림 **매물 원장**(시트 `20_매물원장_필드` 93칸)에 자동으로 채우고, 여러 사이트에 흩어진 같은 차를 **한 줄로 묶어** 보여 준다.

## 2. 흐름
1. 딜러가 등록 화면(nuxt-register)에서 링크를 붙여 넣는다.
2. 보배드림 본 서버가 로그인한 딜러 키(`dealer_key`)와 함께 `POST /listing-imports` 를 부른다.
3. 대기열(Laravel queue, Redis)이 파이썬 작업기 `scripts/listing_import/run.py` 를 한 번 실행한다.
4. 작업기가 링크 1건을 읽고 → 원장 칸(JSON) + 원본 사진을 만든다.
5. 서버가 사진을 저장소(S3 등)로 옮기고, 판매자가 딜러 본인과 맞는지 판정한다(`owner_check`).
6. `본인 매물`·`미판정` 이면 구글 시트 `22_매물원장_데이터` 에 한 줄 추가, `확인 필요` 면 사람 확인 뒤 반영.
7. 딜러 화면은 `GET /dealers/{dealer_key}/listings` 로 흩어진 매물 목록(같은 차 묶음, 사이트별 가격 차이)을 받는다.

- 접속 불가 11곳(울산 국민차·카메카·국민차·오토메카·엠월드·원파크·김해모터스밸리·진영·모터스밸리·엠모터스·디오오토갤러리)은 이 작업 환경(해외 클라우드)에서만 막히고 국내에서는 열린다. 국내 서버에서 다시 시험한다.
- 목록을 사이트 내부 호출(저장 프로시저·AJAX)로만 내주는 단지(오토허브·오토돔)는 그 호출을 쓰지 않는다. 딜러가 상세 주소를 넣으면 읽는다.
- **GG오토(경기도1조합)는 robots.txt 가 전체 수집을 막아 제외**한다.
- 접속 불가(503·연결 끊김·사이트 인증서 오류)는 우리 쪽 보안 설정을 끄지 않는다. 사이트가 고쳐지면 다시 시험한다.
- 판매가 끝난 매물 화면(「현재 판매중인 차량이 아닙니다」)은 `status: 판매완료` 로 남긴다. 숨김 상자 안 같은 문구는 무시한다.
- 같은 차가 조합 사이트와 엔카 등에 동시에 올라 있으면 흩어진 매물 묶기에서 한 줄로 합쳐진다.

## 4. 지키는 원칙 (상용 기준)
- **딜러 본인 매물만.** 판매자 이름·상사가 딜러 정보와 다르면 `확인 필요` 로 멈추고 시트에 쓰지 않는다.
- **한 번에 한 건, 요청 사이 1초.** 대량 수집·목록 순회는 하지 않는다.
- **공개 화면만 읽는다.** 사이트 내부 API를 흉내 내거나 머리글(헤더)을 속이지 않는다.
- **단정어를 쓰지 않는다.** `무사고` 등은 원장에서 지운다(`never_write`).
- **모든 칸은 `미확인` 으로 시작.** 출처 = `다른 사이트`, 사이트 이름을 칸마다 남긴다. 딜러가 확인하면 `확인됨`.
- **차량번호·차대번호·연락처는 내부 전용.** API 응답은 가림(`174오****`, `010-****-2475`), GitHub에는 결과 파일을 올리지 않는다(`data/import-out/`, `data/import-zip/` 는 .gitignore). 시트 22번 탭(내부 원장)에만 원값이 있다.
- **사진은 원본 그대로.** 가공·보정 없음, 같은 내용은 한 장, 2KB 미만은 버림.
- **비밀값은 서버에만.** 서비스 토큰·구글 서비스 계정 키는 서버 환경변수. 화면·GitHub에 두지 않는다.

## 5. 원장 칸 형식
```json
{ "value": "기아", "source": "다른 사이트", "site": "엠파크", "verify": "미확인" }
```
여러 출처 값이 다르면 `verify: "서로 다름"` + `other`. 국토부 조회(vehicle-history)가 연결되면 그 값이 우선이다.

## 6. API (자세한 계약: `listing-import-api/openapi.yaml`)
| 메서드 | 주소 | 설명 |
|---|---|---|
| GET | /api/health | 지원 사이트 목록 |
| POST | /api/listing-imports | 링크 접수(202). 같은 딜러·같은 링크면 기존 결과(200, `existing: true`) |
| GET | /api/listing-imports/{id} | 상태·원장 칸(가림)·사진 |
| POST | /api/listing-imports/{id}/recheck | 가격·판매 상태 다시 확인(1시간에 1번) |
| GET | /api/dealers/{dealerKey}/listings | 흩어진 매물 묶음 |

- 인증: `Authorization: Bearer <서비스 토큰>`(보배드림 본 서버만 호출). 분당 30회.
- 상태: `queued → running → done | needs_review | failed`
- 사이트 이름: 조합·매매단지 매물은 그 사이트 이름(예 `대전카`)으로 돌려준다. `/api/health` 의 `complex_sites` 는 읽을 수 있는 조합·매매단지 사이트 수.
- 오류 코드: `unsupported_site`(422) · `invalid`(422) · `not_found`(404) · `unauthorized`(401) · `too_soon`(429) · 작업 실패 시 `data.error.code` = `extract_failed`(사이트를 읽지 못함) · `worker_failed`(작업기 오류·시간 초과) · `no_ledger`(결과 없음)
- 응답 형식: `{ ok, data }` / 오류 `{ ok:false, error, code }`

## 6-1. 차량 정보 매핑(보배드림 차량 기준표 연결)
사이트마다 차 이름 표기가 다르다(`[기아] 더 뉴쏘렌토 하이브리드(MQ4)`, `르노(삼성) SM6`). 가져온 매물마다 보배드림 차량 기준표(`public/data/vehicle-catalog/cars-index-v1.json`, 제조사 62 · 모델 662 · 세대 1,255)의 id 를 찾아 `ledger.catalog` 에 둔다(`scripts/listing_import/catalog_map.py`).

| match | 뜻 |
|---|---|
| exact | 이름·세대 코드로 세대까지 찾음(예 `더 뉴그랜저IG` → 그랜저 › 더 뉴 그랜저 IG) |
| by_date | 모델은 이름, 세대는 최초등록 연월이 판매 기간 안이라 찾음(예 쏘렌토 MQ4 2025-03 → 더 뉴 쏘렌토 4세대) |
| model · make · none | 모델까지 · 제조사만 · 못 찾음 |

- 제조사 별칭: 르노(삼성)·르노삼성 → 르노코리아(삼성), 쌍용·KGM → KG모빌리티(쌍용), 대우·GM대우 → 쉐보레(GM대우)(국산 차종일 때), 메르세데스-벤츠 → 벤츠, 토요타 → 도요타 등.
- 원장 칸 값(사이트 표기)은 그대로 두고 기준표 값은 따로 둔다. 시트 22번 탭 CQ~CV 열: 기준표 제조사 · 모델 · 세대 · 연결 방식 · 소속 조합 · 연합회.
- 2026-11-23 시험: 24대 중 세대까지 21대(이름 18 · 등록연월 3), 제조사만 3대(포터·봉고 트럭 — 승용 기준표 범위 밖, 트럭 기준표 연결 필요).
- 같은 차 묶기도 기준표 모델 id 를 먼저 쓴다(사이트마다 다른 이름이어도 같은 모델·연식·주행 1% 이내면 한 줄).

## 7. 같은 차 묶기
차량번호 → 차대번호 → 제조사·모델·연식 + 주행거리 차이 1% 이내 순서로 판정. 서버는 `car_key`(sha256)로 묶고 사이트별 가격 차이(`price_gap_krw`)를 낸다. 시트 `23_흩어진_매물` 이 같은 모양이다.

## 8. 운영

- `scripts/listing_import/history_join.py <매물 폴더…>`: 가져온 매물의 차량번호로 보배드림 서버 차량이력 API(`VEHICLE_HISTORY_URL`, 기본 스테이징 시험 주소)를 부르고 원장을 다시 쓴다.
- 보내는 값: 차량번호 · 동의 ID · 목적 `USED_CAR_DEALER_LISTING_CHECK` · 조회 유형 `SALE_VEHICLE_OR_OWNER_UNCONSENTED`(소유자 이름 없이 조회). 기관 키는 서버에만 있다.
- 채우는 칸: 제조사 · 연식 · 정확한 주행거리 · 연료 · 배기량 · 사고(`보험 처리 사고 N건`) · 보험(내차·상대차 피해 건수·금액, 전손·침수·도난) · 용도 이력(소유자 변경 횟수, 렌트·영업용·관용). 국토부 원부가 응답하면 최초등록 · 변속기 · 색상 · 압류·저당도 채운다.
- 사이트 값과 다르면 `서로 다름`으로 두고 사이트 값을 `other`에 남긴다. 주행거리는 사이트가 만 단위 약값이라 기관 값으로 바꾸고 `확인됨(사이트는 약값)`으로 적는다.
- `무사고` 같은 단정어는 쓰지 않는다. 응답 원문은 `history.json`(가린 번호만)으로 작업 폴더에만 둔다.
- 시트 K01~K02: `다른 사이트(…) + 차량이력(카히스토리)` · `일부 확인(차량이력)`.
- 제목에서 `더`·`올`·`뉴` 같은 앞말만 모델로 잘리던 문제를 고쳤다(`common.split_model`).
