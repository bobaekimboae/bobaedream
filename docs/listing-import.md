# 매물 링크 가져오기 (listing-import) 제품 명세 v1

작성: 2026-11-23 · 상태: 상용 1차(서버·작업기 완성, 화면 연결 전)

## 1. 한 줄 요약
딜러가 다른 사이트에 올린 **자기 매물 링크**를 붙여 넣으면, 사진·차량 정보·판매자 정보를 가져와 보배드림 **매물 원장**(시트 `20_매물원장_필드` 93칸)에 자동으로 채우고, 여러 사이트에 흩어진 같은 차를 **한 줄로 묶어** 보여 준다.

## 2. 흐름
1. 딜러가 등록 화면(nuxt-register)에서 링크를 붙여 넣는다.
2. 보배드림 본 서버가 로그인한 딜러 키(`dealer_key`)와 함께 `POST /listing-imports` 를 부른다.
3. 대기열(Laravel queue, Redis)이 파이썬 작업기 `scripts/listing_import/run.py` 를 한 번 실행한다.
4. 작업기가 링크 1건을 읽고 → 원장 칸(JSON) + 원본 사진을 만든다.
5. 서버가 사진을 저장소(S3 등)로 옮기고, 판매자가 딜러 본인과 맞는지 판정한다(`owner_check`).
6. `본인 매물`·`미판정` 이면 구글 시트 `22_매물원장_데이터` 에 한 줄 추가, `확인 필요` 면 사람 확인 뒤 반영.
7. 딜러 화면은 `GET /dealers/{dealer_key}/listings` 로 흩어진 매물 목록(같은 차 묶음, 사이트별 가격 차이)을 받는다.

|---|---|---|---|---|
| 엔카 | 원본 전부(최대 40) | 둘 다 | 딜러·상사·050 | 없음 |

| 코리아카마켓 | 원본 전부 | 차량번호 | 딜러·상사·단지·연락처 | cp949 글자 |
| 차란차 | 대표 1장 | 차량번호 | 050(딜러 이름 없음) | 갤러리·딜러 이름은 딜러가 보충 |

## 4. 지키는 원칙 (상용 기준)
- **딜러 본인 매물만.** 판매자 이름·상사가 딜러 정보와 다르면 `확인 필요` 로 멈추고 시트에 쓰지 않는다.
- **한 번에 한 건, 요청 사이 1초.** 대량 수집·목록 순회는 하지 않는다.
- **공개 화면만 읽는다.** 사이트 내부 API를 흉내 내거나 머리글(헤더)을 속이지 않는다.
- **단정어를 쓰지 않는다.** `무사고` 등은 원장에서 지운다(`never_write`).
- **모든 칸은 `미확인` 으로 시작.** 출처 = `다른 사이트`, 사이트 이름을 칸마다 남긴다. 딜러가 확인하면 `확인됨`.
- **차량번호·차대번호·연락처는 내부 전용.** API 응답은 가림(`174오****`, `010-****-2475`), GitHub에는 결과 파일을 올리지 않는다(`data/import-out/`, `data/import-zip/` 는 .gitignore). 시트 22번 탭(내부 원장)에만 원값이 있다.
- **사진은 원본 그대로.** 가공·보정 없음, 같은 내용은 한 장, 2KB 미만은 버림.
- **비밀값은 서버에만.** 서비스 토큰·구글 서비스 계정 키는 서버 환경변수. 화면·GitHub에 두지 않는다.

## 5. 원장 칸 형식
```json
{ "value": "기아", "source": "다른 사이트", "site": "엠파크", "verify": "미확인" }
```
여러 출처 값이 다르면 `verify: "서로 다름"` + `other`. 국토부 조회(vehicle-history)가 연결되면 그 값이 우선이다.

## 6. API (자세한 계약: `listing-import-api/openapi.yaml`)
| 메서드 | 주소 | 설명 |
|---|---|---|
| GET | /api/health | 지원 사이트 목록 |
| POST | /api/listing-imports | 링크 접수(202). 같은 딜러·같은 링크면 기존 결과(200, `existing: true`) |
| GET | /api/listing-imports/{id} | 상태·원장 칸(가림)·사진 |
| POST | /api/listing-imports/{id}/recheck | 가격·판매 상태 다시 확인(1시간에 1번) |
| GET | /api/dealers/{dealerKey}/listings | 흩어진 매물 묶음 |

- 인증: `Authorization: Bearer <서비스 토큰>`(보배드림 본 서버만 호출). 분당 30회.
- 상태: `queued → running → done | needs_review | failed`
- 오류 코드: `unsupported_site`(422) · `invalid`(422) · `not_found`(404) · `unauthorized`(401) · `too_soon`(429) · 작업 실패 시 `data.error.code` = `extract_failed`(사이트를 읽지 못함) · `worker_failed`(작업기 오류·시간 초과) · `no_ledger`(결과 없음)
- 응답 형식: `{ ok, data }` / 오류 `{ ok:false, error, code }`

## 7. 같은 차 묶기
차량번호 → 차대번호 → 제조사·모델·연식 + 주행거리 차이 1% 이내 순서로 판정. 서버는 `car_key`(sha256)로 묶고 사이트별 가격 차이(`price_gap_krw`)를 낸다. 시트 `23_흩어진_매물` 이 같은 모양이다.

## 8. 운영
- 다시 확인: Laravel 스케줄러(`listing-import-recheck`, 매시)가 마지막 확인 후 `recheck_hours`(기본 24시간) 지난 판매중 매물을 한 번에 50건까지 대기열에 넣어 가격·판매 상태를 갱신. 서버 크론에 `php artisan schedule:run` 을 매분 등록.
- 사이트 화면이 바뀌어 `extract_failed` 가 늘면 그 사이트 어댑터(`scripts/listing_import/sites.py`)만 고친다. 시험: `python3 scripts/listing_import/test_listing_import.py`
- 서버 시험: `bash listing-import-api/tests/smoke.sh`(가짜 작업기, 21개 점검)
