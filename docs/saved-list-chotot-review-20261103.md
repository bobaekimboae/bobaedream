# 저장 목록 PC·모바일 웹 실측 및 컨설팅

대상: 사용자 프론트 Nuxt 4.6.2 / Vue 3.5.33 / TypeScript 6.0.3 / Node 24.22.1 / pnpm 10.33.0. 기존 React 런타임은 보존한다. 운영 업무 API는 Laravel 12 / PHP 8.4 기준이며 이 문서의 브라우저 샘플을 운영 인증·과금 구현으로 간주하지 않는다.

원본: https://www.chotot.com/bookmark/tin-dang-da-luu?site=referrer

## 기존 시안 판정

기존 900px 계정 모달 안의 관심 목록은 원본과 구조가 달랐다. 원본은 전역 헤더를 가진 독립 페이지이며 저장 콘텐츠 탭과 리스트가 하나의 흰 영역을 공유한다. 목록마다 둥근 카드, 상단 샘플 매물 추가 버튼, 사양 설명 줄을 넣은 기존 구현은 원본과 다른 정보 밀도를 만들었다. 원본의 저장 해제는 확인 모달 없이 하트를 비우고 개수를 줄이며 현재 세션의 행을 유지한다.

## 강화 검증 기준

1. 원본 PC/모바일 정상·빈 탭·저장 해제 상태의 캡처와 DOM/스타일 실측을 함께 남긴다.
2. 같은 CSS viewport, 같은 탭/저장 상태의 전체 캡처와 주요 영역 비교 합성본을 실제로 열어 대조한다.
3. 탭·사진·제목·가격·위치·시간·채팅·하트 각각의 크기와 정렬을 확인한다.
4. 카드 열기와 채팅/하트 클릭 영역을 분리하고 중첩 링크를 사용하지 않는다.
5. 탭을 URL query로 표현하고 직접 열기·새로고침·브라우저 뒤로가기를 검사한다.
6. 저장 해제→행 유지→재저장→새로고침 후 실제 저장 내용 반영, 다른 탭의 저장 변경 반영을 검사한다.
7. 안정 샘플 키 기준으로 같은 제목의 다른 매물을 구분하고 중복 저장·100개 한도를 검사한다.
8. 판매 종료/숨김·잘못된 주소·이미지 실패·브라우저 저장 실패에서 성공을 가장하지 않는다.
9. 키보드 활성화, 이름 있는 컨트롤, 포커스 표시, 작은 폭에서 가로 넘침과 오류 안내를 검사한다.
10. 타입/빌드/테스트와 공개 배포 화면 검증을 별도로 수행한다. 빌드 성공만으로 화면 합격을 선언하지 않는다.

## 구현 범위와 완료 판정 경계

- 관심 매물은 독립 Nuxt `/saved` 페이지로 이동한다. PC 상단 관심 버튼, 모바일 저장 목록 버튼과 프로필 메뉴가 같은 페이지를 연다.
- 저장된 실제 시안 매물의 사진·제목·가격·위치·시간을 사용한다. 현재 세션의 해제한 행은 남고 하트/개수만 갱신한다. 새로고침하면 해제한 매물은 제외된다.
- 기존 매물 상세는 저장된 검색 맥락과 샘플 식별 키로 찾아 연다. 운영에서는 안정 매물 ID와 canonical 상세 URL을 API 계약으로 사용해야 한다.
- 매물/영상/게시글 탭과 빈 상태를 분리하며 현재 수집된 데이터의 개수만 표시한다. 영상·게시글 실제 저장 어댑터는 미연결이다. 0건 탭 전환을 영상·게시글 저장 기능 완성으로 판정하지 않는다.
- 채팅 버튼은 매물 맥락이 있는 독립 문의 화면을 연다. 문의 초안 임시 저장만 지원하며 판매자에게 실제 전송하지 않는다. 실제 채팅, 계정 간 동기화, 운영 알림은 서버 연동 완료 전까지 미완료다.
- 브라우저 저장 실패 시 하트·개수는 변경하지 않는다. 쓰기 전 최신 목록을 읽어 오래된 다른 탭의 데이터로 덮어쓰지 않는다.

전체 서비스의 '초톳과 모든 기능 동일' 판정은 위 미연결 영역까지 포함해 보류해야 한다. 시각 QA 합격과 운영 기능 합격은 다른 판정이다. 우선 운영 API에 회원별 저장 콘텐츠(kind/id/availability/canonical URL), 저장/해제 멱등성, 100개 한도, 판매 상태 갱신, 삭제/차단, 채팅 대화방 진입 및 접근 권한 계약을 확정해야 한다.

## 권장 후속 순서

운영 저장 목록 API → 영상·게시글 저장 생산 화면 연결 → 실제 채팅 서버 연결 → 로그인/다른 기기 동기화 → 판매 종료·차단·권한 오류 회귀검사 순서가 적합하다. 기존 글/영상 숫자를 임의로 채우거나 전송되지 않은 문의를 '전송 완료'로 표시하지 않는다.

## 실제 검사 결과 (2026-11-03)

- Nuxt 단위 테스트 24개, 타입 검사, 정적 생성 통과. 루트 전체 verify도 통과: 보호 런타임 28개, admin/catalog 테스트 29개, Sites 테스트 4개, TypeScript/Vite 빌드.
- PC 1280×900: 본문 최대 1140px, 사진 168px. 모바일 390×844: 사진 128px, 제목 2줄, body 가용 폭 386.4px, 가로 넘침 0, 깨진 이미지 0. 원본·구현 합성 캡처를 열어 세 차례 수정 대조했다.
- 모바일 빈 탭의 하트 y=306.375px로 원본과 일치한다. 빈 영역 외부 12px 누락과 불필요한 강제 줄바꿈, 헤더 채팅 아이콘/로고 중앙 정렬을 수정했다.
- 해제 시 현재 행 유지/개수 감소, 재저장, 새로고침, 영상·게시글 URL 탭, 뒤로가기, 판매 완료 매물 진입 제한, 문의 초안 저장/복원을 브라우저에서 확인했다.
- 저장 원본이 PC URL이어도 휴대폰에서 강제 PC 화면을 열지 않도록 현재 화면 크기로 pc 파라미터를 정규화한다. 단위 테스트에 교차 화면 사례를 추가했다.
- 실제 시안 카니발을 저장 후 열어 제목, 7,450만원, 서민호 판매자가 일치함을 확인했다. 기존 PC 상세가 일부 선택 차량에 Bentley 비교 문구를 표시하던 조건문 한 곳을 수정했다. 새 React 화면을 작성하지 않았으며 기존 비교용 상세는 보존한다.
- 시각/브라우저 샘플 범위 판정만 합격이다. 운영 서버, 실제 채팅, 영상·게시글 저장, 다른 기기 동기화는 미완료이며 최종 오픈 판정에서 제외할 수 없다.

증거: Codex 시각화 폴더 `saved-list-chotot-20261103`의 PC·모바일 정상/빈 탭 및 합성 비교 캡처. 원본 계정 캡처는 비공개 로컬 증거로만 보존하며 저장소에 올리지 않는다.

저장 한도 추가 회귀검사: 기존 목록 브리지의 101번째 저장이 오래된 항목을 밀어내던 동작을 차단했다. 로컬 검증용 100개 목록에서 초과 클릭 시 한도 안내, 하트 false, 기존 100개 보존을 브라우저로 확인했다. 저장 실패도 원래 하트 상태를 유지하고 오류를 표시한다.

이전 sample-* 항목의 축약 제목(기아 카니발 하이리무진)도 구성 단어와 가격이 모두 같은 시안 매물로 연결한다. 이전 문자열 startsWith 비교가 세대명이 끼어든 제목을 찾지 못하던 오류를 수정했고 7,450만원 카니발 상세 진입을 확인했다. 운영 안정 ID를 대체하는 규칙은 아니며 이전 샘플 호환에만 한정한다. 목록 브리지 캐시 버전도 갱신했다.
