## 1. 작업 기준

- 보배드림 설치 앱(2026-10-20): `/app/`에서 현재 파랑 심벌·빨간 점 로고와 `보배드림` 이름의 Android APK 및 설치형 웹앱을 제공한다. APK 소스는 `apps/android-prototype/`, 빌드는 `python apps/android-prototype/build.py`(JDK + Android SDK 36/Build Tools 36). 설치 파일·해시·메타데이터는 `public/app/`에 둔다. 앱 ID는 `io.github.bobaekimboae.bobaedream`으로 공식 앱과 분리하며, 실행 주소는 프로젝트 메인이다. APK는 기존 시안을 WebView로 여는 온라인 앱이며 인터넷 권한만 쓴다. 서명 키/암호는 사용자 로컬 `.codex/app-signing/`에만 있고 저장소에 넣지 않는다. 업데이트 때 키를 보존하고 Manifest의 버전 코드를 올린다. PWA는 프로젝트 범위에서만 동작하며 매물 HTML을 캐시하지 않는다. 검증은 `node --test tests/installable-app.test.mjs`, 전체 `npm run verify`, APK 서명/정렬/패키지 정보 검사다. 실기기 설치·실행은 별도 확인이 필요하다.
- 앱 아이콘 텍스트(2026-10-20): 현재 심벌 아래에 헤더 로고의 `보배드림` 글자 벡터를 흰색으로 배치한다. 일반 아이콘·PWA 원형 마스크용·Android 적응형 전경을 각각 안전 영역에 맞춘다. Android 1.0.1(버전 코드 2)은 기존과 같은 키로 서명해 업데이트 설치한다. 웹 아이콘 URL과 오프라인 로고 캐시도 v2로 갱신한다.


- 사용자 작업 방식(2026-10-18): 이 프로젝트의 수정 요청은 별도 배포 확인을 다시 묻지 않고, 검증 후 기존 GitHub Pages에 먼저 배포한 다음 결과를 보고한다.
- 기본 작업 화면은 `?qf=guazi` 개발 시안형이다.
- PC는 기본 `&pc=1` 개발 시안형만 수정한다.
- ChoTot 비교 화면(`&pcl=chotot`)과 Dongchedi 모드는 사용자가 별도로 요청하지 않는 한 수정하지 않는다.
- 공통 수치와 동작 규칙의 단일 기준은 `docs/quick-filter-spec.md`다.

## 2. 이번 최종 반영 범위

### 판매자 유형 바텀시트

- 상단 제목은 `판매자 유형` 한 줄만 사용한다. 부제는 없다.
- 헤더 높이 64, 좌측 여백 24, 제목 20/28·750, 하단 구분선 1px `#E8E8E8`.
- 닫기 버튼은 44×44 터치 영역 안에 24×24 X를 사용한다. 위치는 위 10, 오른쪽 20이다.
- 본문은 헤더 아래 16부터 시작하고 좌우 여백은 20이다.
- 설명이 없는 행은 높이 54, 설명이 있는 행은 높이 68이다.
- 체크박스는 20×20, 아이콘 칸은 32×32, 열 간격은 12다.
- 선택 상태는 노란 배경을 사용하지 않는다. 검은 채움과 흰 체크마크를 사용한다.
- 하단 액션 영역은 높이 80, 좌우 여백 20, 버튼 간격 10이다. 초기화는 92×52, 선택하기는 남은 폭×52다.
- 임시 선택은 `선택하기`에서만 적용한다. 닫기·배경·Escape·브라우저 뒤로가기는 임시 선택을 버린다.
- React Strict Mode에서 effect 재실행 때문에 시트가 즉시 닫히지 않도록 history marker 정리를 지연하고 재설정 시 취소한다.

### 상단 필터칩

- 현재 시안 작업 필터인 `판매자`는 PC와 모바일 모두 고정 `필터` 버튼 바로 오른쪽에 둔다.
- 판매자 조건이 없을 때는 일반 `판매자` 칩을 표시한다.
- 판매자 조건이 적용되면 같은 자리를 진한 적용 칩과 X로 교체한다.
- 판매자 적용 칩을 일반 적용 칩 묶음으로 이동시키지 않는다.
- 나머지 칩의 상대 순서와 동작은 기존 Guazi 규칙을 유지한다.

## 4. 모바일 매물 리스트 확정 기준

- 차명은 임의 줄바꿈이 아니라 의미 기준 2줄이다. 1줄은 제조사·모델, 2줄은 세부모델·트림이며 각 줄을 독립적으로 한 줄 말줄임한다.
- 리스트형은 제목 15px, 스펙·지역 13px, 가격 16px이고 피드형은 제목 16px, 스펙·지역 14px, 가격 17px이다. 가격 단위는 두 보기 모두 14px이다.
- 연월 정보가 있으면 차란차식 `24년08월`로 표시한다(월 두 자리, 띄어쓰기·`식` 없음). 월 정보가 없는 데이터만 `24년식`으로 표시하며 원본 값은 바꾸지 않고 목록 표시 단계에서 정규화한다.
- 매물 카드의 미선택 찜 아이콘은 초톳 참고 SVG(24px, `#8C8C8C`)를 사용하고, 선택 상태는 같은 실루엣에 활성 색상만 적용한다.
- 모바일 목록형·피드형의 찜 버튼은 당근 카드처럼 차명 첫째 줄 오른쪽에 둔다. 아이콘 여백은 제조사·모델 줄에만 확보하고 세부모델·트림 줄 폭은 줄이지 않는다. 갤러리형은 사진 위, 텍스트형은 기존 우측 상단 배치를 유지한다.
- 판매자 프사는 목록형·피드형 모두 20×20px 원형이며 중앙 기준 `cover`로 자른다. 초톳 원본 50개는 보존하되 광고·차량·브랜드/매장 로고는 프사로 연결하지 않는다. 승인된 인물 사진은 보이는 매물끼리 중복 없이 배치하고 사진이 없는 판매자는 기존 기본 프로필 아이콘을 쓴다.
- 피드형 직접 검수 주소는 `?qf=guazi&view=feed`, 목록형은 기본 `?qf=guazi`다.
- 배지가 없는 카드는 배지 자리를 접는다. 고정 195px 최소 높이를 다시 넣지 않는다. 모바일 판매자 줄의 `판매중` 문구도 표시하지 않는다.
- 개인 매물은 지역만 표시한다. 개인 외 판매자는 `지역 · 실제 단지명`을 표시하며, 임의의 `지역 + 매매단지` 문구를 만들지 않는다.
- 실제 단지명은 KB차차차 지역별 매매단지 마스터의 `지역별_매매단지` 자료를 기준으로 한다. 단지의 실제 소재지와 카드 지역이 다르면 소재지를 함께 교정한다.
- 목록에서만 `자동차매매단지`·`매매단지`를 `단지`로 줄인다. `도이치오토월드`, `서울오토갤러리` 같은 고유명은 줄이지 않는다. 정식 명칭은 원본 데이터와 상세 화면에서 유지할 수 있다.
- 현재 표시 매핑은 `src/prototype/data/index.tsx`의 `dealerComplexByRegion`, 공통 표시 규칙은 `displayListPlace`가 담당한다. 모바일·PC·보기 방식별로 별도 문구를 하드코딩하지 않는다.

- 목록에 `자동차매매단지` 또는 `매매단지` 전체 문구가 반복 노출되지 않는다.
- 배지 없는 카드에 빈 배지 공간이나 고정 최소 높이가 남지 않는다.

## 9. 매물 등록 화면(JOB-7)

- `?register`로 연다(`?register=form`은 1단계를 건너뛰고 폼부터). 기준은 dev `https://dev.bbmuseum.co.kr/car/register` → `/car/register/form`(2026-10-07 실측)이다.
- 코드: `src/prototype/register/`(`index.tsx` 화면·팝업, `ui.tsx` 입력 부품, `data.ts` 선택지·목업, `header-html.ts` PC 헤더·운영정책 원문, `inspection-pc-html.ts` PC 점검기록부 원문). 자산은 `public/assets/register/`.
- 모양은 dev 원본 CSS 중 등록 화면이 쓰는 규칙만 뽑아 `.bbm-register` 아래로 묶은 `register.css`가 그린다. 클래스 이름은 dev와 같게 유지한다. 팝업은 dev처럼 화면 루트 바로 아래(포털)에 붙인다.

## 10. 상세 화면 표기 규칙(2026-10-13, 중고차 상세 초톳 동일화)

- 상세 상단(사진·썸네일 아래)은 목록 카드(`BbmResultCard`)와 같은 컴포넌트·CSS를 쓰고 사진·판매자 줄만 숨긴다. 글자 크기는 초톳 상세 캡처 실측값(제목 19 · 메타 14 · 가격 20 · 지역 15)이다. 세부는 `docs/quick-filter-spec.md`의 「중고차 상세 …」 항목들.
- **법인 표기 생략**: 상사명·딜러명에서 `주식회사`와 `(주)`는 화면에 쓰지 않는다(예: `주식회사 에이엠씨인터내셔널` → `에이엠씨인터내셔널`). 목록 카드·피드(`dealer` 만들 때 `replace(/\(주\)|주식회사/g, "")`)와 상세(`stripCorp`) 모두 같다. 데이터 원본 파일의 상사명은 그대로 두고 표시할 때만 뺀다. 새 상사명을 화면에 넣을 때도 이 규칙을 지킨다.
- **연식 표기**: 월을 알면 `24년08월`(두 자리 월·붙여 쓰기·`식` 없음), 최초등록 연도와 연형이 다르면 `23년08월(22년형)`(차란차 방식), 월을 모르면 숫자 4자리 `2024`.
- 지역 줄은 `시도 구군 · 매매단지 · 상사명`을 한 줄로 잇되 길어서 넘치면 상사명이 통째로 아랫줄로 내려간다(아랫줄 맨 앞 점 없음, 법인 표기 생략). 그 아래 시계 아이콘 + `등록 N일 전`, 그 아래 판매자 영역(프사 · `이름 딜러` · `N대 판매완료 · N대 판매중`)이다. 상사는 판매자 영역 안에 두지 않는다. 판매완료 대수는 가상 값이다.
- 하트는 제목 첫 줄 오른쪽 끝(목록 하트와 같은 위치·아이콘)이다. 큰 사진 가운데 점은 쓰지 않고 `1 / N` 개수와 썸네일 줄(80×60, 선택 `#222` 테두리)만 쓴다.
- 페라리 실제 상세(`ferrari-detail-v01.ts`)는 차란차 3대만 연결돼 있다. 시트(`페라리 매물 상세정보 입력용_2026-10-13`)의 옵션 전체·사진 5장·전국연합 5대는 시트 CSV가 저장소에 오면 마저 연결한다.
- 지역 줄의 매매단지 · 상사명은 이동할 곳이 있는 항목에만 밑줄 링크(에어비앤비 방식)를 건다: 단지 → 카테고리 목록, 상사명 → 서울오토갤러리 딜러 페이지(5명). 링크 대상을 늘리려면 `detail/index.tsx`의 `locationLinks`만 고친다.
