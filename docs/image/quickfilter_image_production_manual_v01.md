# 보배드림 퀵필터 이미지 생산 매뉴얼 v01

- 작성일: 2026-10-04
- 적용 대상: 승용·바이크·트럭/특장·건설기계·캠핑카·버스·농기계·부품/용품의 **탐색용 퀵필터 이미지**
- 제외 대상: 실제 매물 사진, 메인 배너, 프로모션용 3/4 이미지
- 목표: 제작자가 바뀌거나 100개를 연속 제작해도 같은 슬롯에서 99% 이상 동일한 품질 기준을 통과하게 한다.

## 1. 99% 동일 품질의 정확한 뜻

생성형 이미지는 같은 문장을 다시 입력해도 픽셀이 완전히 같지 않다. 따라서 이 문서에서 99%는 픽셀 복제가 아니라 아래 **10개 생산 규격의 합격률**을 뜻한다.

1. 방향: 앞머리 왼쪽, 정확한 90° 정측면
2. 투영: 원근 왜곡이 거의 없는 카탈로그형 측면
3. 대상 완전성: 앞·뒤·바퀴·미러·붐·적재함 등 식별 부위가 잘리지 않음
4. 투명도: 배경은 실제 알파 투명, 흰 사각형과 외곽 halo 없음
5. 점유율: 매니페스트의 안전 상자 안에 허용 오차 ±2px
6. 기준선: 바퀴·트랙·지면 접점이 지정 기준선 ±2px
7. 중심: 가시 바운딩 박스 중심이 캔버스 중심 ±2px
8. 조명·색: 고정 팔레트와 중성 스튜디오 조명
9. 그림자: 얕은 접지 그림자만 사용, 대상보다 넓거나 진하지 않음
10. 파일: 이름·버전·캔버스·알파·중복 검사를 모두 통과

100개 중 99개 이상이 위 자동·수동 검수를 모두 통과하면 `99% 동일 품질`로 판정한다. 한 번 승인한 마스터는 다시 생성하지 않는다. 수정은 새 버전으로만 만든다.

## 2. 이미지 용도를 먼저 분리한다

| 구분 | 사용 위치 | 방향 | 처리 |
|---|---|---|---|
| 분류형 | 퀵필터, 카테고리 레일, 바텀시트 | 앞머리 왼쪽 90° 정측면 | 본 매뉴얼 적용 |
| 홍보형 | 메인 카테고리, 배너, 추천 영역 | 좌향 3/4 허용 | 별도 규격 |
| 매물형 | 실제 매물 목록·상세 | 실제 촬영 각도 보존 | `cover`, 본 매뉴얼 미적용 |

분류형에 3/4 이미지를 섞지 않는다. 카캐리어·윙바디·굴착기처럼 구조가 긴 대상은 3/4에서 전면부만 커져 분류 특징이 약해지므로 정측면을 사용한다. 승용·바이크도 같은 규칙을 적용해 카테고리가 바뀌어도 기준이 흔들리지 않게 한다.

## 3. 고정 사양

### 3.0 슬롯 UX의 최상위 기준

퀵필터의 슬롯·피치·가로 레일·라벨·모바일/PC 반응형 운용은 **초톳을 최상위 UX 기준**으로 삼는다. 경쟁사 자료는 초톳 규칙을 대체하지 않고, 고해상도 원본 제작과 촬영 규율을 보강하는 용도로만 사용한다.

- 초톳에서 직접 측정한 값은 `초톳 실측값`으로 기록한다.
- 초톳 PC에서 직접 확인하지 못한 값은 초톳 값이라고 쓰지 않고 `보배드림 PC 채택값`으로 기록한다.
- 모바일과 PC는 같은 승인 마스터를 사용하고 슬롯 래퍼만 바꾼다.
- PC 화면이 넓어도 이미지를 과도하게 키우지 않고 더 많은 항목을 보여준다.
- 카드 내부 이미지와 라벨의 광학 중심, 첫 시작선, 반복 피치를 화면별로 고정한다.

### 3.1 마스터와 웹 파생본

| 항목 | 값 |
|---|---|
| 승인 마스터 | 가능한 최고 해상도 RGBA PNG, 긴 변 1024px 이상 권장 |
| 정규화 캔버스 | 512×320px, RGBA, 8:5 |
| 기본 안전 상자 | 448×224px |
| 기본 수평 중심 | x=256 |
| 기본 지면 기준선 | y=262 |
| 알파 검출 임계값 | 12/255 |
| 최종 표시 | 모바일 64×40, PC 76×40, `object-fit: contain`, `center bottom` |
| 파일 색공간 | sRGB |

마스터를 CSS 슬롯 크기로 직접 만들지 않는다. 승인 마스터에서 512×320 파생본을 코드로 만들고, 브라우저가 이를 64×40 또는 76×40으로 축소한다.

### 3.2 초톳 기준 UI 슬롯

| 표면 | 값의 성격 | 셀 | 이미지 | 간격 | 첫 시작 | 이미지→명칭 | 명칭 |
|---|---|---:|---:|---:|---:|---:|---|
| 모바일 퀵필터 | 초톳 실측 | 76×102 | 64×40 | 8 | 16 | 14 | 14/20, 최대 2줄 |
| PC 퀵필터 | 보배드림 채택 | 84×102 | 76×40 | 8 | 20 | 14 | 14/20, 최대 2줄 |

이미지 파일 안에 UI 여백을 굽지 않는다. 투명 파생본은 512×320 공통 캔버스를 사용하고 실제 여백은 슬롯과 CSS가 담당한다.

## 4. 촬영·렌더 규칙

### 4.1 모든 카테고리에 공통인 불변 조건

- 피사체 앞머리는 왼쪽을 향한다.
- 카메라는 대상의 측면 중앙에 수직으로 둔다.
- 카메라 높이는 승용·트럭·바이크는 차축 높이, 건설기계는 트랙/바퀴 중심 높이를 기준으로 한다.
- 전면·후면·상판이 보이는 3/4 원근은 불합격이다.
- 실제 제조사 카탈로그 수준의 재질과 기계 구조를 사용하되, 로고·상표·번호판·문자·워터마크는 넣지 않는다.
- 흰색 배경처럼 보이는 불투명 픽셀을 금지하고 실제 투명 알파를 사용한다.
- 광원은 좌상단 45°의 큰 소프트박스 1개와 약한 정면 필로 고정한다.
- 색온도는 중성 5500K, 과한 HDR·광택·렌즈 플레어를 금지한다.
- 접지 그림자는 대상 바로 아래에만 두며 검정이 아닌 중성 회색, 시각 불투명도 8~12%로 제한한다.
- 사람, 소품, 도로, 건물, 먼지, 연기, 바닥선은 넣지 않는다.

### 4.2 카테고리별 팔레트와 식별 규칙

| 카테고리 | 기본 색 | 반드시 보이는 구조 |
|---|---|---|
| 승용 | 펄 화이트·라이트 실버 | 앞·뒤 범퍼, 루프, 네 바퀴 |
| 바이크 | 무채색 차체 + 제한된 한 가지 포인트색 | 앞·뒤 바퀴, 핸들, 시트, 엔진/배터리부 |
| 트럭/특장 | 흰색 캡 + 기능부 중성 회색 | 캡, 축, 적재/특장 장치 전체 |
| 건설기계 | 안전 노랑 + 차콜 | 붐·버킷·트랙/타이어 전체 |
| 캠핑카/버스 | 화이트 + 라이트 실버 | 차체 전장, 창 배열, 오버캡/출입문 |
| 농기계 | 한 세트 안에서 고정한 제조사 비종속색 | 작업기와 바퀴 전체 |
| 부품/용품 | 실물 고유색, 한 카드에 한 대상 | 제품 외곽과 연결부 전체 |

윙바디는 양쪽 날개가 열린 모습으로 제작해 탑차·냉동탑차와 즉시 구분한다. 냉동·냉장차는 상단 또는 전면 냉동기를 반드시 보이게 한다. 굴착기·크레인처럼 외곽이 긴 대상은 붐을 운송 가능한 낮은 자세로 접되 핵심 부착물이 가려지지 않게 한다.

## 5. 파일·버전·폴더 규칙

```text
public/assets/quickfilter/{category_code}/{type_code}/
  master/{category_code}_{type_code}_side_master_v01.png
  web/{category_code}_{type_code}_side_v01.png
```

- 영문 소문자, 숫자, 밑줄만 사용한다.
- 버전은 `v01 → v02 → v03`으로 올린다.
- 기존 승인 파일을 덮어쓰지 않는다.
- 방향 표기는 분류형에서 항상 `_side_`다.
- 승인 마스터와 웹 파생본의 버전은 반드시 같다.
- 새 버전을 만들면 매니페스트와 변경기록을 같은 커밋에서 갱신한다.

## 6. 표준 생산 흐름

### 6.1 생성 전

1. 제조사 공식 홈페이지의 정측면 사진과 치수도를 구조 참고용으로 조사한다.
2. 매니페스트에 한국어명, 코드, 핵심 식별점, 색, 안전 상자, 기준선을 먼저 입력한다.
3. 같은 생산 묶음의 `style_anchor`를 하나 지정한다. 승인된 첫 이미지가 앵커이며 중간에 바꾸지 않는다.
4. 고정 프롬프트의 불변 문장은 수정하지 않고 변수 칸만 채운다.

### 6.2 생성

1. 서로 다른 대상은 한 장에 묶지 않고 **대상별 한 번의 이미지 생성 호출**로 만든다.
2. 출력 배경은 투명을 요청한다.
3. 첫 결과에서 한 번에 여러 문제를 수정하지 않는다. 구조, 방향, 그림자 순으로 한 항목씩 교정한다.
4. 반복 편집 때도 방향·투명·조명·색·금지 요소를 매번 다시 명시한다.
5. 기준 이미지가 있으면 `Image 1: style reference`, 수정 대상이면 `Image 1: edit target`처럼 역할을 명시한다.

### 6.3 승인과 파생

1. 정측면·구조·잘림·투명 배경을 사람이 검수한다.
2. 합격한 파일만 `master`에 넣고 상태를 `master_approved`로 바꾼다.
3. `scripts/normalize-quickfilter-image.py`로 512×320 파생본을 만든다.
4. `scripts/check-quickfilter-images.py`로 기계 검수를 실행한다.
5. 64×40 축소 미리보기에서 대상이 한눈에 구분되는지 사람이 다시 확인한다.
6. 자동·수동 검수가 모두 끝난 파일만 제품 코드에 연결한다.

## 7. 정규화 규칙

정규화는 눈대중으로 하지 않는다. 매니페스트 한 행의 숫자를 기준으로 다음 순서로 처리한다.

1. 알파값 12 이상인 픽셀의 바운딩 박스를 구한다.
2. 그 박스만 잘라낸다.
3. 가로·세로 비율은 바꾸지 않는다.
4. `target_width`와 `target_height` 안에 들어가는 최대 배율로 축소한다.
5. 가시 박스 중심을 `anchor_x`에 맞춘다.
6. 가시 박스 하단을 `baseline_y`에 맞춘다.
7. 512×320 투명 캔버스에 합성한다.
8. PNG 최적화 후 저장한다.

긴 대상·높은 대상도 임의 확대/축소하지 않는다. 예외는 매니페스트의 목표 상자 값으로만 관리하며, 스크립트 코드를 항목별로 분기하지 않는다.

## 8. 자동 실패 조건

다음 중 하나라도 해당하면 배포하지 않는다.

- 캔버스가 512×320이 아님
- RGBA 또는 알파 채널이 없음
- 네 모서리 중 하나라도 불투명
- 가시 픽셀이 없음
- 가시 바운딩 박스가 목표 상자를 초과함
- 중심 또는 기준선 오차가 2px를 초과함
- 파일명이 매니페스트와 다름
- 동일 해시의 이미지가 둘 이상 존재함
- `manual_orientation_qa`, `manual_structure_qa`, `manual_small_slot_qa` 중 하나가 `PASS`가 아님

자동 검수는 기계 구조와 방향을 완전히 판별하지 못한다. 따라서 세 개의 수동 검수 열은 생략할 수 없다.

## 9. 수동 검수표

| 항목 | PASS 기준 |
|---|---|
| 방향 | 앞머리 왼쪽, 정확한 정측면 |
| 원근 | 전면·후면·상판 면이 두드러지지 않음 |
| 구조 | 실제 장비/차량으로 가능한 구조, 축·바퀴·장치 수가 자연스러움 |
| 식별 | 64×40에서도 같은 묶음의 다른 유형과 구분됨 |
| 잘림 | 외곽과 핵심 장치가 모두 보임 |
| 색·조명 | 같은 묶음에서 색온도·노출·채도가 같음 |
| 그림자 | 얕은 접지감만 주며 외곽을 흐리지 않음 |
| 금지 요소 | 로고·문자·번호판·사람·배경·워터마크 없음 |

## 10. 100개 양산 관리

- 10개 단위로 배치를 나눈다: `batch_01`부터 `batch_10`.
- 각 배치 첫 이미지는 승인 앵커와 나란히 비교한다.
- 배치마다 자동 검수 결과와 64×40 연락판을 저장한다.
- 10개 중 1개라도 방향·색온도·점유율이 이탈하면 해당 배치 전체를 재검수한다.
- 100개 완료 후 합격 수/전체 수를 기록한다. 목표는 `99/100 이상`이다.
- 불합격 이미지는 삭제하지 않고 `rejected/`에 버전과 사유를 보존한다.
- 승인된 99개를 다시 생성해 맞추려 하지 않는다. 불합격 항목만 새 버전으로 교정한다.

## 11. 벤치마크에서 채택한 부분

- 초톳: 슬롯 UX의 최상위 기준. 모바일 슬롯 크기·피치·라벨 간격과 모바일/PC 공용 자산 운용 원칙
- Carsales: 정측면, 진행 방향, 투명 배경, 차체·그림자 정렬을 명시하는 제작 규율
- AutoScout24·AutoTrader Canada: 작은 슬롯에서도 보이는 고해상도 카탈로그 컷과 카테고리 간 시각적 일관성

보배드림 최종 규칙은 `초톳의 모바일·PC 슬롯 UX + Carsales의 제작 규율 + AutoScout24/AutoTrader 수준의 원본 품질`이다.

## 12. 실행 명령

```powershell
python scripts/normalize-quickfilter-image.py --manifest docs/image/quickfilter_image_pilot_manifest_v01.csv
python scripts/check-quickfilter-images.py --manifest docs/image/quickfilter_image_pilot_manifest_v01.csv --report reports/quickfilter-image-pilot-v01.json
```

검수 프로그램이 `FAIL`을 반환하면 제품 연결과 배포를 중단한다.
