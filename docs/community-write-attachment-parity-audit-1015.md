# 게시물 등록폼 이미지 첨부 전수조사 — 2026-10-15

## 조사 기준

- 로그인된 네이버 카페 모바일 웹 글쓰기 화면을 읽기 전용으로 확인했다.
- 실제 게시·임시등록·외부 전송은 하지 않았다.
- 사진/파일/동영상 버튼의 파일 선택기 속성과 네이버 공식 고객센터 문서를 교차 확인했다.
- 네이버 로고·서비스 문구·원본 이미지는 복제하지 않고, 보배드림 시안의 아이콘과 Airbnb 계열 기본색을 유지했다.

## 원본 동작 근거

| 항목 | 확인 결과 | 구현 |
|---|---|---|
| 사진 선택 | 다중 선택, `.jpg,.jpeg,.gif,.png,.bmp,.heic,.heif,.webp` | 동일 accept + 다중 선택 |
| 사진 한도 | 장당 20MB, 게시글당 100장 | 혼합 선택 시 유효 파일만 부분 성공, 초과 이유 표시 |
| 입력 방식 | 버튼 선택, 원하는 위치로 끌어오기 | 파일 선택, 본문 드래그앤드롭, 클립보드 붙여넣기 |
| 선택 사진 편집 | 대표, 크기, 정렬, 링크, 캡션, 교체, 삭제 | 사진 선택 시 속성 툴바 노출 |
| 대표 사진 | 문서에서 한 장만 선택 | 새 문서 첫 사진 자동 지정, 다른 사진 지정 시 단일 전환 |
| 사진 크기 | 작게, 문서 너비, 옆트임 | 3개 모드 구현 |
| 사진 편집 | 회전·반전·비율·필터 등 | 회전, 좌우 반전, 1:1·4:3·16:9, 자동·흑백·웜 필터 |
| 순서 변경 | 사진을 끌어서 재배치 | 사진 블록 드래그 재정렬 |
| 삭제 | 삭제 버튼 또는 키보드 삭제 | 개별 삭제, 선택 상태 Delete/Backspace |
| 임시저장 | PC/모바일에서 이어쓰기 | 본문 메타는 localStorage, 이미지 Blob은 IndexedDB에 저장·복원 |
| 일반 파일 | 최대 10개, 개당 50MB | 선택 1회 1개, 누적 10개, 50MB 제한 |
| 동영상 | 원본 선택기는 단일 파일, `video/*` | 기존 URL 카드 방식 유지. 파일 업로드는 후속 서버 업로더 연결 필요 |

## 오류·경계 시나리오

| 시나리오 | 결과 |
|---|---|
| 이미지가 아닌 파일 | 해당 파일만 제외하고 이유 안내 |
| 20MB 초과 | 첨부하지 않고 파일명·원인 안내 |
| 100장 초과 | 앞 100장만 처리, 나머지 제외 건수 안내 |
| 정상+오류 혼합 | 정상 이미지는 유지, 오류만 모아 안내 |
| 파일 선택 취소 | 기존 본문과 선택 상태 유지 |
| 같은 사진 교체 | 캡션·대표·정렬·크기·링크·편집 상태 유지 |
| 마지막 대표 사진 삭제 | 남은 첫 사진을 대표로 자동 지정 |
| 새로고침 후 임시글 | Blob URL 대신 IndexedDB에서 다시 생성해 깨진 이미지 방지 |
| 드래그 대상이 사진이 아님 | 본문을 바꾸지 않고 지원 형식 안내 |
| 모바일 좁은 폭 | 속성 툴바 가로 스크롤, 본문 가로 넘침 없음 |

## 의도적으로 제외한 범위

- 네이버 서버 업로드, 바이러스 검사, MYBOX 연동, 360VR/파노라마 변환은 정적 GitHub Pages 시안에서 재현할 수 없다.
- 모자이크·서명·스티커 합성처럼 픽셀을 새 파일로 다시 인코딩하는 고급 포토에디터는 브라우저 CSS 미리보기가 아니라 별도 이미지 처리 모듈이 필요하다. 이번 범위는 등록폼의 첨부·선택·배치·속성·복원 흐름이다.
