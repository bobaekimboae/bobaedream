> **이 파이프라인의 관건은 「차량 정보 매핑」이다.** 사진이든 영상이든 컷 하나하나를 읽고(무엇이 보이는가), 그 컷에 맞는 차량 설명(매물 정보의 사실)을 짝지어 주는 능력. 그다음이 **옵션마다 그림 붙이기(13장)** 이고, 편집 효과·음악·자막 꾸밈은 그 뒤다. 7장과 13장을 먼저 읽는다.

## 1. 전체 흐름

```
원본 영상(또는 사진) + 매물 정보
 → ⓪ 컷 읽기 · 차량 정보 매핑(7장) ← 가장 중요
 → ① 원본 맞추기(FFmpeg)
 → ② 대본 쓰기(BLOCKS) — 필수 옵션 빠짐 검사(13장)
 → ③ 음성 만들기(일레븐랩스) → ④ 낱말 시각 받기(일레븐랩스 받아쓰기)
 → ④-1 옵션 비주얼 자동 배치(13장: 낱말 → 컷 → 부위 → 그림)
 → ⑤ 렌더(scripts/shortform/sag_reel_v1.py 또는 photo_listing/common.py: 컷 · 자막 · 스티커 · 음악 · 소리 크기)
 → ⑥ 눈으로 확인(장면 모음 · LUFS · 매핑 검수)
 → ⑦ 샘플 페이지 갱신 → PR → 「배포해」 후 병합 → GitHub Pages
 → ⑧ 노션 기록
```

## 3. 단계별 방법

### ① 원본 맞추기
```
ffmpeg -i 원본.mp4 -vf "scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,fps=30" -an -c:v libx264 -crf 18 norm.mp4
```
부위가 시작하는 초를 적어 둔다(외관 정면 · 측면 · 후면 · 휠 · 실내 · 센터 · 선루프 · 뒷좌석 · 운전석 · 트렁크). 이 기록이 7장 매핑표의 왼쪽 칸이다.

### ② 대본 — `scripts/shortform/sag_reel_v1.py`의 `CAR` · `BLOCKS`
- 신차 리뷰 순서, 「~습니다」: 「오늘 리뷰할 차는 ○○입니다. 가격은 ○○만 원」 → 연식 · 코드네임 · 세대 · 엔진 · 구동 → 「디자인부터 보시죠」 → 휠 → 후면 → 「실내로 들어가 보겠습니다」 → 트렁크 용량 → 「정리하면」 등록 연월 · 주행 · 가격 → 「자세한 내용은 보배드림 앱에서 확인하시면 됩니다」.
- 사실만: 매물 정보 · 영상에 보이는 것 · 그 차종 공식 제원. 모르는 것(사고 이력 등)은 말하지 않는다.
- 문장 하나는 7장 매핑표의 한 줄(컷 하나)에서 나온다. 컷에 안 보이는 사실을 억지로 그 컷에 붙이지 않는다.
- 매물 옵션 중 13장 필수 옵션(시트 재질·열선·통풍·마사지·휠·트렁크·라이트·스피커·화면·카메라·마력)은 반드시 한 문장씩 넣는다.
- 블록 칸: `sec`(부위) · `tts`(읽을 문장, 숫자는 읽는 대로: 포, 구칠일, 사백구십오 리터) · `caps`(화면 자막 구절, 숫자로) · `shots`[(원본 초, 속도, 번호판 여부)] · `stickers`[(글자, 구절 번호)] · 첫 블록 `hook=True`, 마지막 `end=True`.
- 읽는 말 → 화면 글자 바꾸기는 `SHOW` 사전(예: 구칠일 → 971).

### ③ 음성
- 모델 eleven_v4(MCP 이름 기준) · 목소리 「Mr.J - Korean Creator」(voice_id `HvCQYI15cbdFVC9pSBfb`).
- 블록의 `tts`를 줄바꿈으로 이어 한 번에 만든다. 2테이크 중 하나 고르기. 전체 약 $0.09/테이크.
- 한 문장만 바꿀 때: 그 문장만 만들고, 원본의 문장 사이 무음(`ffmpeg -af silencedetect=n=-40dB:d=0.06`) 가운데에서 잘라 이어 붙인다.
- 생성은 다시 시도하려고 반복하지 않는다(매번 비용).

### ④ 낱말 시각
- 받아쓰기 결과를 `[{"text": "오늘", "start": 0.0, "end": 0.24}, …]` 모양 JSON으로 저장.
- 이어 붙인 문장은 받아쓰기 없이 글자 수 비율로 시각을 나눠 넣어도 된다.

### ⑤ 렌더
```
SAG_VOICE_FILE=voice.mp3 SAG_VOICE_WORDS=words.json python3 scripts/shortform/sag_reel_v1.py norm.mp4 out/
python3 scripts/shortform/photo_listing/common.py <차 폴더>          # 사진 매물
```
- 결과: `out/sag_reel_v1.mp4` · `out/meta.json`. 약 4분.
- `SAG_VOICE_FILE`이 없으면 edge-tts 임시 음성으로 만든다(서비스용으로 쓰지 않음).
- 끝나면 `scripts/shortform/__pycache__` 삭제(커밋하지 않음).

### ⑥ 확인
```
ffmpeg -i out/sag_reel_v1.mp4 -af ebur128 -f null - 2>&1 | grep -A1 Integrated   # 약 -14 LUFS
ffmpeg -i out/sag_reel_v1.mp4 -vf "fps=1/2.5,scale=180:-1,tile=9x3" -frames:v 1 sheet.jpg
```
장면 모음에서 자막 · 스티커 · 세이프존 · 끝 카드를 눈으로 본다. 그리고 7-5 매핑 검수표와 13-6 옵션 그림 검수를 채운다.

### ⑦ 샘플 페이지 · 배포
```
ffmpeg -i out/sag_reel_v1.mp4 -c:v libx264 -preset veryfast -crf 24 -maxrate 3M -bufsize 6M -pix_fmt yuv420p -c:a aac -b:a 128k -movflags +faststart public/shortform-samples/sag-reel-v1/panamera-v1.mp4
```
- `poster.jpg`(0.8초 장면), `index.html`의 대본 줄(`rows`)과 「만드는 방식」 갱신.
- 새 브랜치 → 커밋 → PR. 병합 · 배포는 「배포해」를 받은 뒤. 배포 후 `?v=<커밋 7자리>`로 페이지 · 영상 200 확인.

## 5. 지킬 것
- 사진 · 영상은 자르기 · 이동 · 확대 · 색 보정만. 배경 지우기 · AI 생성 금지.
- 다른 회사(오토스카우트24 · 나세르 등)의 그림 파일 · 로고는 쓰지 않는다. 구조와 칠 방식만 배워 새로 그린다. 나세르 영상은 내부 분석용이며 다시 게시하지 않는다.
- 다른 회사 워터마크가 찍힌 사진(예: 다른 매물 사이트 로고)은 지우지 않는다. 그런 사진으로 만든 영상은 내부 훈련용으로만 쓰고 게시하지 않는다.
- 개인 연락처 · 차량번호 · 차대번호를 자막 · 글에 쓰지 않는다. 연락처나 차대번호 판이 크게 찍힌 사진은 컷에서 뺀다.
- 이모지는 Microsoft Fluent 3D만(`fluent3d/`). 코드네임은 BMW · 벤츠 · 포르쉐만.
- 새 서비스 코드는 리뉴얼 기술 스택(Nuxt 4 · Vue 3 · TS / Laravel 12). 이 Python 스크립트는 시안 · 샘플 제작용.

- 옵션 그림 자동 배치(`auto_visuals.py`, 13-5)
- 서비스화: 같은 입력을 Laravel 작업 대기열 워커로 돌리기

## 7. 컷 읽기 · 차량 정보 매핑 (핵심 능력)

숏폼의 품질은 「이 컷에 무엇이 보이는가」와 「그때 무슨 말을 하는가」가 맞는지로 결정된다. 사진 매물이든 영상 매물이든 같은 절차를 따른다.

### 7-1. 컷 읽기 — 컷마다 적을 것
| 칸 | 내용 | 예 |
|---|---|---|
| 컷 번호 · 출처 | 사진 번호 또는 영상 시작·끝 초 | p09 / 12.4~15.1초 |
| 부위 | 정해진 부위 이름 하나 | 앞 45° · 정면 · 옆면 · 뒤 45° · 후면 · 휠·타이어 · 헤드라이트 · 계기판 · 대시보드 · 센터 화면 · 시트 · 뒷좌석 · 스피커 · 트렁크 · 엔진룸 · 적재함 · 적재함 실측 · 특장 장비 · 캡 실내 · 하부 |
| 보이는 것 | 사진에서 직접 확인되는 것만 | 디지털 계기판, 줄자 화면 8.93m, 엠블럼 크게 보임 |
| 상태 | 흔들림 · 어두움 · 해상도 · 워터마크 · 가려야 할 것 | 667×500 작음, 워터마크 있음 |
| 쓸지 | 쓴다 / 뺀다 + 이유 | 뺌: 차대번호 판 |

### 7-2. 차량 정보 정리 — 사실 목록
- 매물 정보에서만 뽑는다: 제조사 · 모델 · 세부형식 · 연식(차란차 표기) · 주행 · 연료 · 변속기 · 마력·배기량 · 구동·축 · 적재·제원 · 옵션 · 이력(보험·압류·저당·구조변경·소유자 변경) · 가격 · 지역.
- 사이트의 일괄 태그처럼 이 차에 실제로 있는지 확인되지 않는 항목은 뺀다.
- 다른 회사 자체 서비스(그 사이트의 인증·보증·대출)는 넣지 않는다.
- 판매자 주장(무사고·1인 신조 등)은 「판매자 기재」로 표시해 두고, 매물 정보의 숫자(보험 이력 0건 등)로 뒷받침될 때만 말한다.

### 7-3. 매핑 규칙 — 사실을 어느 컷에 붙이나
| 사실 | 붙일 컷(우선순위) |
|---|---|
| 제조사 · 모델 · 연식 | 첫 컷(엠블럼 → 정면·앞 45°) |
| 주행 · 이력(0건 목록) | 앞 45° · 정면 등 차 전체가 보이는 컷 |
| 마력 · 배기량 · 구동 · 축 | 옆면(축·바퀴 배열이 보임) · 엔진룸 |
| 변속기 · 연료 | 옆면 · 실내(기어 레버가 보이면 실내 우선) |
| 적재함 · 트렁크 크기 | 적재함·트렁크 컷, 실측 사진이 있으면 그 컷에 큰 숫자 |
| 옵션 | 그 옵션이 보이는 컷 + 13장 그림. 보이지 않는 옵션은 실내 일반 컷에 칩으로만 |
| 계기판 · 화면 | 계기판·센터 화면 컷(보이는 것만 말함) |
| 휠 · 타이어 | 휠·타이어 컷(상태 평가는 하지 않고 「확인해 보세요」) |
| 가격 · 지역 | 마지막 차 전체 컷 + 끝 카드 |

- 한 컷에 사실은 1~2개. 3개 이상이면 ✓ 목록 칩으로 쌓는다.
- 사실이 없는 좋은 컷은 짧게(2초) 이어 주는 컷으로 쓰고 말을 억지로 붙이지 않는다.
- 사실은 있는데 맞는 컷이 없으면 차 전체 컷에 칩으로만 띄우거나 뺀다. 다른 부위 컷에 붙이지 않는다.

### 7-4. 매핑표 형식 (대본·렌더의 입력)
`컷 | 사진/초 | 부위 | 화면(칩·큰 숫자·옵션 그림) | 내레이션 | 근거(매물 정보 항목)`
근거 칸이 비어 있는 줄은 내레이션을 쓰지 않는다.

### 7-5. 매핑 검수 (렌더 후)
- 장면 모음에서 칩·자막이 뜨는 순간의 컷이 매핑표의 부위와 같은가
- 말하는 부위와 보이는 부위가 0.5초 넘게 어긋나는 곳이 없는가
- 근거 없는 숫자·옵션·평가가 0개인가
- 연락처·차대번호가 보이는 컷이 0개인가

## 8. 첫 컷 — 엠블럼 · 브랜드 · 모델 · 연식 (2026-11-17 확정, A안)
- 0~0.8초: 실제 매물 사진(또는 영상) 속 엠블럼에 확대해서 시작. 자르기·확대만 하고 로고 파일은 얹지 않는다.
- 0.8~1.6초: 뒤로 빠지며 차 전체가 보이고 타이틀이 아래에서 올라옴.
- 1.6초~: 타이틀 고정. 위에서부터 제조사 → 모델(가장 크게) → 연식 · 주행 칩. 타이틀은 벨기에(AS24 BE) 뼈대대로 화면 위 15~35% 띠(세로 중심 약 24%)에 둔다. 첫 컷 타이틀이 떠 있는 동안 말 자막은 숨기고, 그 뒤로는 자막을 항상 보인다.
- 첫 컷 길이 3~4초, 처음 3초 안에 컷을 바꾸지 않는다(나세르 330편 실측: 첫 컷 중앙값 4.3초, 81%가 3초 안에 컷 없음).
- 엠블럼이 작거나 흐리면 확대 단계를 건너뛰고 차 전체부터 시작.
- 연식은 차란차 표기(23년08월 / 연형이 다르면 23년08월(22년형) / 월 모르면 2023), 코드네임은 BMW · 벤츠 · 포르쉐만.

## 9. 화물 · 특장 매물 (2026-11-17 훈련: 현대 파비스 11톤 카고)
- 길이: 60초를 채우지 않는다. 쓸 수 있는 사진·사실 양에 맞춰 40초 안팎(13컷 · 컷 3초 · 0.5초 페이드).
- 트럭 구매자가 먼저 보는 사실 순서: 톤수·형식 → 연식·주행 → 이력 0건 → 마력·축 → 변속기·연료 → 적재함 길이·폭·파렛트 → 옵션(무시동 에어컨 등) → 가격·지역.
- 적재함 실측 사진(줄자·레이저 측정기)이 있으면 그 컷에 실측값 큰 숫자. 매물 정보의 적재함 길이와 맞는지 확인한다.
- 옆면 컷에서 축 배열(6x2 등)과 바퀴 수가 보이므로 마력·축을 붙인다.
- 하부·프레임 사진은 흔들리고 어두운 경우가 많아 기본 제외, 깨끗하면 2초 이어 주는 컷.
- 사진이 작으면(667×500 등) 세로 화면에 꽉 채우지 않고 차 전체를 상자에 맞추고 남는 곳은 같은 사진 흐림으로 채운다.

### 9-1. 트럭 제원 읽는 법 (2026-11-17 학습, 파비스 공식 제원표 대조)
- **축 표기 `N x M`**: 앞 숫자 = 바퀴 자리 수(축 수 × 2), 뒤 숫자 = 엔진 힘이 가는 바퀴 자리 수. 4x2 = 2축 중 뒤 1축 구동, 6x2 = 3축 중 1축 구동(나머지 1축은 가변축), 6x4 = 3축 중 2축 구동(덤프·트랙터), 8x4 = 4축 중 2축 구동.
- **가변축**: 들어 올렸다 내리는 보조축(비구동). 빈 차일 때 올리고 짐을 실으면 내려 하중을 나눈다. 구동축 앞에 붙으면 앞가변(푸셔), 뒤에 붙으면 뒤가변·「후축」(태그). 매물 표기 「6X2 후축」 = 구동축 뒤에 가변축 1개. 현대 파비스 카탈로그는 6x2를 「태그 액슬(푸셔 액슬 미운영)」이라고 적는다.
- **톤수 = 최대적재량**: 가변축을 더하면 같은 차에서 톤수가 올라간다(파비스 카탈로그: 「가변축 추가를 통해 카고 출고 시 8톤에서 13.5톤까지」). 축 하나당 10톤, 총중량 40톤이 과적 기준.
- **장축 계열 = 축간거리·적재함 길이**: 파비스 카고 공식 제원(내측 길이 × 폭): 장축 5,300 × 2,280 · 초장축 6,250 · 초장축플러스7.0 7,000 · 극초장축7.4 7,400 × 2,350 · 극초장축플러스7.6 7,600 · 8.3 8,300 · 8.9 8,900 × 2,350. 모델 이름 숫자 = 적재함 길이(m).
- **매물 값과 공식 제원 대조(필수)**: 매물 정보의 축·톤·적재함이 공식 출고 사양과 다르면 특장(가변축 추가·적재함 제작)을 거친 차다. 이번 파비스 매물: 「6X2 후축 · 11톤 · 8,900 × 2,410」. 공장 출고 카고에서 8,900 적재함은 4x2(8.5톤)뿐이고, 6x2 카고는 7,400·7,600(8/13.5톤), 11톤과 폭 2,410은 공식표에 없다. 그런데 매물은 「특장업체: 없음(순정)」, 모델년도 2026이라 2025 제원표에 없는 26년형 사양일 수도 있다(26년형 제원표는 아직 대조 못 함). **추정(특장 개조 등)은 대본에 쓰지 않는다.** 매물 표기만 말하고, 확정은 자동차등록증(최대적재량·총중량·축간거리)으로 한다.
- **매물 사이트 옵션 목록 주의**: 아이트럭 「주요 옵션」에는 보링·변속기 수리·파워게이트 같은 점검 체크 항목이 섞여 나온다. 사진이나 판매자 설명으로 확인되는 것(무시동 에어컨·히터)만 쓴다. 매물 사이트의 자체 보증(정밀진단·수리비 보장)은 넣지 않는다. 검사 유효기간이 지난 값도 말하지 않는다.
- **대본·칩 규칙**: 톤수는 매물 표기 그대로(「11톤」), 축은 「6x2 후축(뒤 가변축)」처럼 풀어 말할 수 있다. 적재함은 매물의 내측 길이·폭, 실측 사진이 있으면 실측값 큰 숫자. 마력·축 칩은 축 배열이 보이는 옆면 컷에.
- 출처: 현대 파비스 2025-04 제원표·2025-06 카탈로그(hyundai.com), 아이트럭 매물 259711, 가변축·과적 기준 다음 카페 글.

- 카드 구성(1080×1920): 매물 사진 흐린 배경 위 종이 상자(폭 940, 모서리 28) → 남색 머리 「성능·상태 점검기록부 · 핵심 요약」 → 차명 줄 → 성능지 원본에서 **차체 그림만** 잘라 붙임(첫 줄이 켜질 때 초록 도장 「표시 없음 · 사고 부위」) → 체크 줄 5개(초록 원 ✓ + 항목 + 오른쪽 「없음」) → 아래 출처 한 줄.
- 체크 줄에 쓰는 항목(성능지에 있는 칸만): 사고 이력·단순 수리 / 침수·화재(특별 이력) / 렌트·리스·영업용(용도 변경) / 튜닝·리콜 / 엔진·변속기 누유 + 주요 장치 양호. 「있음」인 항목은 숨기지 않고 그대로 적는다(딜러 확인 후).
- **잘라 쓰지 않는 곳:** 차량번호 · 차대번호 · 제시번호 · 검사자/업체 정보 칸. 차체 그림 칸만 쓴다. 성능지 주행거리와 딜러 글 주행거리가 다르면(점검 당시 vs 현재) 딜러 글(현재)을 말하고, 성능지 숫자는 카드에 쓰지 않는다.
- 대본: 「자, 성능점검 기록부. 핵심만 읽어 드립니다」 → 줄마다 한 문장(「사고 이력, 단순 수리, 없습니다」…). 한 문장 = 한 단계 컷.
- 보험 이력 카드(`insurance`)와 차량 개요 카드(`overview`)도 같은 방식. 보험 이력에 내 차 피해가 있으면 숨기지 않고 「내 차 피해 1회」처럼 적는다(딜러 「무사고」 주장과 다르면 매물 숫자를 따른다).

### 12-2. 가격 인하 카드
- 같은 `cards.json`의 `price` → `p30`(신차가만) · `p31`(신차가에 빨간 X줄 + ▼ + 할인 판매가, 노랑 형광 띠). 위에 매물 사진 16:9.
- 신차가·인하 사유는 딜러 글에 있는 것만(예: 「매입 1년 가까이 · 판매가격 인하」).

### 12-3. cfg 쓰는 법
- 카드 컷은 켄번스 정지 `(.5,.5,1.0,1.0,.5)`. 첫 카드는 `dip_white`(가격은 `dip_black`)로 장을 바꾸고, 다음 단계부터 넘김 **`'reveal'`**(0.18초 겹침, 확대 없음) → 같은 카드에서 한 줄씩 켜지는 것처럼 보이고, 단계마다 팝 소리.
- `CAP_CY_PHOTOS={20:1660, …, 30:1600, 31:1600}` — 카드 컷 동안 말 자막을 카드 아래로.
- 미리 만든 9:16 그림(1080×1920)은 `BBM_FADE=1`에서도 상자 맞춤 없이 그대로 나온다.
- 카드 컷에는 노랑 칩을 띄우지 않는다(카드가 칩 역할). 다음 사진 컷으로 돌아올 때 `fade_long`.

## 13. 옵션 비주얼 자동 규칙 — 나세르 기준 (v1.5, 2026-11-18)
전체본: `docs/shortform/option-visual-rules-v1.md` · 기계용 값: `scripts/shortform/photo_listing/option_visual_rules.json`. **이 장의 규칙은 차마다 손으로 정하지 않는다. 모든 차에 같은 규칙이 자동으로 걸린다.**

### 13-1. 왜
나세르 영상은 짧은데 리뷰 한 편을 본 느낌이 난다. 옵션 기능을 말할 때마다 그 기능의 그림이 하나씩 붙어서, 말을 다 듣지 않아도 눈으로 쏙쏙 이해되기 때문이다(나세르 177편 · 옵션 장면 1,134개 분석: 작동 시연 49% · 아이콘 26% · 글자 카드 18%). 우리 원칙: **옵션 문장 하나 = 그림 하나.**

### 13-2. 필수 옵션 — 매물에 있으면 반드시 말하고 그림을 띄운다
| 옵션 | 나세르 언급률 | 우리 그림 |
|---|---|---|
| 화면 | 43% | 👆 손가락 탭 + 3D 글자 크기 `12.3"` |
| 휠 | 37% | 3D 글자 `21"` |
| 열선 | 37% | 🔥 Fluent 3D |
| 통풍 | 34% | ❄️ Fluent 3D |
| 카메라 | 28% | 📷 Fluent 3D |
| 트렁크 | 21% | 3D 글자 `770 L` |
| 라이트 | 18% | 3D 글자 종류 `LED` · `매트릭스 LED` · `레이저` · `HID` · `DRL` (나세르 「DRLs」「HD METRIX」처럼) |
| 마사지 | 16% | 💆 Fluent 3D |
| 스피커 | 15% | 3D 글자 브랜드 + 개수 `BOSE x14` |
| 엔진·마력 | 14% | 3D 글자 `340 마력` |
| **시트 재질** | 5% → **우리는 필수** | 3D 글자 `나파 가죽` · `알칸타라` |

- **시트 사진이 있으면 재질 + 열선 · 통풍 · 마사지(+ 메모리)는 그 시트 컷에서 반드시 말로 설명하고 Fluent 3D 아이콘을 띄운다(나세르 방식, 사용자 지시 2026-11-18).** 시트 컷 대본에 그 낱말이 없으면 렌더가 멈춘다(⛔ 「시트 컷 대본에 없음」). 아이콘은 등받이 위에 한 줄(🔥 → ❄️ → 💆 → 💾), 크기·간격·자리는 오픈소스 부위 찾기(OWLv2)가 찾은 등받이 상자에 맞춘다 — 13-10.
- **나세르가 필수로 설명하고 그림을 띄우는 옵션은, 우리도 그 부위 사진이 있으면 똑같이 한다.** 사진이 없으면 실내 일반 컷에 노랑 칩으로만 말하고 그림은 얹지 않는다(다른 부위 사진에 그림 금지).
- 필수 아님(있으면 같은 방식): 공조 🌬️ · 무선충전 ⚡ · 선루프 `파노라마` · 앰비언트 `64색` · HUD.
- 그림 글자의 값(인치·리터·브랜드·라이트 종류·재질·마력)은 매물 정보에서만. 값이 없으면 그 그림을 빼고 말도 하지 않는다.

### 13-3. 그림 종류
1. Fluent 3D 스티커 — 기능(열선·통풍·마사지·카메라·무선충전·공조). `fluent3d/` 폴더, 없으면 렌더 중단.
2. 3D 글자 — 이름·숫자. 흰 굵은 글자 + 아래쪽 회색 두께 + 얇은 검은 외곽선(`common.py` `text3d()`).
3. 손가락 👆 — 누르는·돌리는·당기는 조작부가 보일 때와 주행거리·가격 칩. 한 컷 1개.

### 13-4. 위치 · 크기
- 3D 글자 높이: 숫자 = 화면 높이 10%(약 190px), 낱말 = 6%(약 115px), 단위 = 숫자의 0.5배.
- 자리: 부위 바로 위(화면 2% 띄움) → 자리가 없으면 옆. 부위·말 자막 띠·아래 딜러 띠를 가리지 않는다. 한 컷에 그림 최대 2개.
- 등장: 그 낱말 소리 0.05초 전에 톡(0.32초 튀는 곡선), 라이트·선루프는 바로. 그 컷 끝 0.12초 전까지 유지. 사진 확대·이동을 따라간다.
- 효과음: 그림마다 팝, 마력은 딩, 선루프는 휙. 0.45초 안에 겹치면 하나만.

### 13-5. 자동화 흐름
```
매물 정보 JSON(옵션·값) + 낱말 시각 + 컷 목록(사진·부위)
 → ① 필수 검사(required 옵션이 대본에 없으면 실패)
 → ② 낱말 찾기(keywords) → 그 낱말이 든 컷 → 사진 부위가 option.part인지
 → ③ STICKERS · POINTERS 자동 생성(값은 매물 정보에서)
 → ④ part_anchor.py(OWLv2)로 부위 상자 → 사진 안 좌표
 → ⑤ 자리 잡기(부위 위 → 옆, 겹치면 밀어냄)
 → ⑥ 렌더 → ⑦ 검사
```
cfg에는 `AUTO_VISUALS = True`와 `LISTING_OPTIONS = {'wheel': {'inch': 21}, 'trunk': {'liters': 770}, 'seat_heat': {}, 'light': {'light_type': 'LED'}, ...}`만 적는다. 손으로 적은 STICKERS·TAGS가 있으면 그것이 우선.

### 13-6. 옵션 그림 검수
- 그림 없이 지나간 옵션 문장 0개
- 그림이 다른 부위 위에 뜬 곳 0개(열선 아이콘이 휠 위 등)
- 매물 정보에 없는 값(인치·리터·브랜드) 0개
- 매물에 있는 필수 옵션 중 대본에서 빠진 것 0개

### 13-10. 시트 묶음 · 휠 크기 · 숫자 화면 표기 (v1.6.1, 2026-11-18 사용자 지시)
| 규칙 | 값 (`option_visual_rules.json`) |
|---|---|

## 14. 부위 당기기 — 키프레임 자동 (v1.2, 2026-11-18 사용자 지시)
규칙 파일: `scripts/shortform/photo_listing/part_zoom_rules.json` · 코드: `part_zoom.py` · cfg: `AUTO_ZOOM = True`. **한 대만 손으로 키프레임을 적지 않는다. 어떤 경우에 당길지를 규칙으로 정하고 모든 차에 같이 건다.**

### 14-1. 왜
정지에 가까운 사진(확대 1.0 → 1.06)만 이어지면 「정사진만 보여 준다」. 나세르는 부위를 말할 때 화면이 그 부위로 다가간다(옵션 장면 49%가 작동 시연·근접).

### 14-2. 당기는 경우
| 경우 | 동작 |
|---|---|
| 컷 라벨에 작은 부위 낱말(계기판·화면·시계·다이얼·레버·콘솔·버튼·공조·핸들) | 그 부위로 당김 |
| 실내 컷에서 라벨에 없어도 작은 부위를 말함(「터치스크린 … 계기판은」) | 말한 순서대로 최대 2개 이어서(화면 → 계기판) |
| 외관 컷에서 휠·라이트를 말함(「21인치 … 휠」) | 그 낱말에 맞춰 휠·라이트로 당김. 휠·라이트는 외관 컷 전용 |
| 시트 컷(앞좌석·운전석·시트) | 등받이만(시트 아이콘 줄이 화면에 남게). 같은 문장의 「핸들」로 가지 않음 |
| 작은 부위와 큰 부위가 같이 걸림(「뒷좌석 공조」) | 작은 부위만(공조) |

### 14-3. 당기지 않는 경우(약한 밀기 또는 그대로)
| 경우 | 처리 |
|---|---|
| 첫 컷(엠블럼 → 뒤로 빠지기) · FIT 사진 · 9:16 카드 · cfg에 손 키프레임 | 그대로 |
| 컷 1.6초 미만 | 그대로 |
| 부위를 못 찾음 / 점수 0.20 미만 / 상자가 사진의 35% 초과(이미 근접 사진) / 큰 부위(시트·트렁크·루프) | 약한 밀기 1.0 → 1.12(부위 쪽으로 반만 치우침). **움직임 6% 미만 정지 사진은 만들지 않는다** |

### 14-4. 움직임 · 크기
- 컷 시작은 넓게(z 1.0, 부위 쪽으로 30% 치우침) → 그 부위 낱말 소리 0.10초 전 출발, 0.60초 감속으로 도착 → 컷 끝까지 3% 더 천천히. 낱말이 없으면 컷 35% 지점 도착.
- 크기: 부위 상자 폭이 화면 폭의 70%(높이 80% 이하). 한계: 9:16 전체화면 z 1.7, 페이드형 z 2.6, 원본 픽셀 3배 이하(흐림 방지).
- 손가락(👆 u·v) 표적은 당긴 화면 안에 남도록 줌 상자를 넓힌다. 스티커·3D 글자는 사진 변환(AFF)을 따라가므로 함께 움직인다.
- 부위 찾기: `part_anchor.py`(OWLv2)에 gauge·clock·dial·stalk·climate 프롬프트 추가. 결과·못 찾음은 `src2/pNN.anchors.json`에 저장(다음 렌더는 모델을 다시 돌리지 않음).

### 14-5. 검사
렌더 로그 `[부위 당기기]` 줄로 컷마다 당김/약한 밀기/그대로와 이유를 확인하고, 도착 시각 장면을 뽑아 부위가 화면 가운데·크게 보이는지 본다. 카이엔 v12 결과: 대시보드 → 화면(z 1.69) → 계기판(z 1.22), 뒤 45° → 휠(z 1.69), 공조 패널, 나머지 근접 사진은 약한 밀기.


## 15. 영상 매물 나세르형 — 벤츠 G350 블루텍 (v1.6, 2026-11-19 사용자 지시)

실제 촬영 영상(131초) 하나로 69초 판매 숏폼을 만든 과정에서 정한 규칙. 코드: `scripts/shortform/video_listing/` (README 참고). 결과: v1 59초 → v2 64초 → v3 69초 → v4(보조 칩 교체·여백 통일).

### 15-1. 사실 출처
- 숫자는 매물 정보 + 화면에 보이는 것 + 사용자가 준 제원(ADAC · 다나와)만. 다나와 2013 G350 블루텍: V6 2,987cc · 211마력 · 토크 55kg·m · 7단 자동 · 265/60 R18 · 제로백 9.1초. ADAC: 트렁크 480L(접으면 2,250L) · 견인 3,500kg.

### 15-2. 대본 · 음성
- 하오체 금지. 「입니다」와 「요」를 섞어 실제 중고차 판매 숏폼처럼 쓴다(나세르식: 기능을 보여 주며 쓰임새를 짧게 설명).
- 화면에 나오는 장치는 원리를 한 문장으로 설명한다(예: 디퍼렌셜 락 = 앞·가운데·뒤 잠금 → 바퀴 하나가 헛돌아도 힘을 나눠 줘서 진흙길·눈길 탈출).
- 한 문장만 고칠 때는 그 문장만 같은 목소리로 한 번 생성해 무음 구간에 끼운다(전체 재녹음 금지). 끼운 뒤 낱말 시각 다시 받기.
- 받아쓰기 오탈자는 FIX 표로 고친다(블루텟→블루텍, 주관 등→주간등, 제 눈→제논, 보베드림→보배드림, 55kgm→55kg·m 등).

### 15-3. 칩 · 화살표 · 트래킹
- 부위가 보이는 컷은 노랑 붓칠 칩 + 화살표가 부위를 따라간다(CSRT 트래킹). 화살표는 부위가 실제로 보이는 원본 구간(av)에서만 그린다.
- 칩의 위·아래 자리는 컷 안에서 고정(뒤집힘 방지), 아래쪽 칩은 화면 58% 높이를 넘지 않는다.
- 부위가 금방 화면을 벗어나는 짧은 컷은 재생 속도를 0.55배로 낮춰 끝 프레임에서 멈추게 한다.

### 15-4. 숫자 · 아이콘
- 큰 숫자는 3D 글자(180px, 마력은 210px). 타이어 규격(265/60 R18)처럼 숫자·기호가 섞인 값은 앞 숫자만 커지지 않게 한 크기로.
- 시트: 재질 3D 글자 + Fluent 3D 🔥 열선 · ❄️ 통풍을 그 낱말에 톡. 메모리 시트는 디스켓 💾 금지 → 💺 + 노랑 원 숫자 ①②③(버튼 개수).
- 아이콘은 Fluent 3D만. 없는 이모지는 microsoft/fluentui-emoji 공식 저장소에서 받는다(🔒 1f512 추가).
- 오토스카우트 선 아이콘(engine · gearbox · trunk · tyre)은 진한 글자색으로 칠해 보조 칩 안에 쓴다. `power.svg`는 AutoUncle 것이라 쓰지 않는다.

### 15-5. 보조 칩 = AS24 테마 붓칠 흰색 (직접 그린 흰 알약 폐지)
- 핵심 정보는 노랑 붓칠 칩, 그 아래 보조 정보(토크·변속기·제로백, 트렁크 「기본」「뒷좌석 접으면」, 「앞·가운데·뒤 잠금」 등)는 **같은 AS24 테마 붓칠 원본에 색만 흰색**. 짧은 글 `126_40.svg`, 칠 폭 520px 넘으면 `265_42.svg`. 새 색을 늘리지 않고 색으로 위계를 만든다.
- 비교한 6안: 흰 알약 / 임모스카우트 민트 태그(「프리미엄_민트_67_20」) / 임모스카우트 단계 숫자 원(「1_42_42」) / AS24 형광펜 민트 / AS24 붓칠 흰색(채택) / AS24 붓칠 민트. 민트 태그는 2순위(보조 정보를 더 튀게 할 때). 단계 숫자 원은 메모리 ①②③과 겹쳐 제외.
- 노션 기록: 에이전트 의견 「숏폼 보조 칩 — 흰 알약 대신 AS24 테마 붓칠 흰색」.

### 15-6. 칩 여백 통일 (노랑·흰 같은 공식)
- 높이 = 글자 높이 × 1.9, 좌우 여백 = 높이 × 0.31.
- 붓 끝이 들쭉날쭉하므로 **칠의 가운데 높이 줄에서 실제로 칠해진 가로 구간**을 재서 그 폭이 「내용 폭 + 여백 × 2」가 되도록 가로 크기를 맞추고, 글자·아이콘을 그 구간 가운데에 둔다.
- 측정(`chip_margin_check.py`): 노랑 36/32px, 흰 30~37px로 맞춤. 고치기 전 흰 칩은 63~82px로 2배였다. 밝은 금색 아이콘(🔒)은 측정에서 빠지니 눈으로 확인.

### 15-7. 효과음
- 매뉴얼 13장 아이콘 효과음(v1.7)을 영상 매물에도 적용: 시트 열선·통풍·메모리 아이콘이 톡 나올 때 `pop.wav` 0.30. 딩·다른 효과음과 0.45초 안이면 생략, 아이콘끼리 0.45초 안이면 앞의 것만.
- 숫자 딩(0.7)은 견인 3,500kg · 트렁크 480L. 마력은 딩 대신 말 울음 효과음(ElevenLabs 효과음 1회 생성, 1.42초로 자르고 페이드아웃, 0.55)을 「211」 낱말 끝에, 🐎 아이콘과 같이.
- 섞기: 목소리 highpass 70 + 압축(−20dB, 3:1) · 배경음 0.16 · loudnorm I=−10 → 192kHz 오버샘플 리미터 0.76 → 결과 약 −14.7 LUFS, 최고점 약 −2dB.
