# 카드 정보 독립 컷 매뉴얼 v1 (2026-11-26, 클로드 시안 1)

매물의 성능점검·보험이력·옵션 같은 정보를 흰 카드 한 장에 정리해 차례로 보여 주는 숏폼 컷이다. 엔카에서는 이 정보를 보려면 여러 번 눌러야 한다. 이 컷은 같은 정보를 영상 한 컷 안에 요약해서 보여 주는 것을 차별점으로 삼는다.

- 코드: `scripts/shortform/card_info/render_cards.py`
- 화면·시간·소리 값: `scripts/shortform/card_info/cards_spec.json`(값은 이 파일 한 곳에만 둔다)
- 노랑·음량: `scripts/shortform/be_locked_rules.json`(벨기에판 기준을 그대로 읽는다)
- 입력 예시: `scripts/shortform/card_info/samples/g400d_cards.json`(벤츠 G400d, 차란차 공개 매물 화면에서 읽은 값)

## 1. 화면 구조 (1080×1920, 30fps)

| 층 | 위치 | 내용 |
|---|---|---|
| 배경 | 화면 전체 | 그 카드에 맞는 매물 사진을 화면에 꽉 차게 키운다. 흐림 28, 어둡게 45%. 5.5초 동안 1.00배에서 1.06배까지 천천히 확대 |
| 사진 띠 | y 120, 좌우 60 | 흐리지 않은 같은 사진. 높이 420, 모서리 28. 카드가 길면 최소 240까지 줄인다 |
| 차명 | 사진 띠 아래 | `제조사 모델` 46 ExtraBold 흰색, 아래 줄에 `등록연월 · 주행 · 연료` 34. 그림자 있음 |
| 카드 | 가운데, 폭 960 | 흰 바탕, 모서리 36, 안쪽 여백 44, 아래쪽에 부드러운 그림자 |
| 요약 자막 | y 1740 | 64 ExtraBold, 흰 글자에 그림자. 강조 낱말만 노랑 #F5F200. 자막 뒤에 칠은 넣지 않는다 |

카드 머리 = Fluent 3D 아이콘 72 + 종류 이름 34 + 차 짧은 이름 28(회색) → 노랑 붓칠 칩 제목 58 → 구분선 `#ECECEC`.
붓칠 칩은 노션 원본 `265_42`를 3분할로 늘려서 쓴다(`brushfill.theme_mask_sliced`). 칠 높이는 글자 높이의 2.0배이고, 글자는 가운데에서 글자 높이의 6%만큼 위로 올린다.

## 2. 움직임 (`timing`)

| 시점 | 동작 |
|---|---|
| 0~0.45초 | 카드가 아래에서 80px 떠오르며 나타난다(감속 곡선). 휙 효과음 |
| 0.5초 | 요약 자막이 한 번에 뜬다 |
| 0.6초부터 0.32초마다 | 행·칸이 하나씩 나타난다. 0.25초 동안 20px 떠오르며 투명→불투명. 처음 3개만 톡 효과음 |
| 막대형 | 막대가 0.6초 동안 자라고, 숫자가 0부터 세어 올라간다 |
| 마지막 조각 + 2.6초 | 끝. 마지막 0.3초 동안 카드와 자막이 사라진다. 한 컷 길이는 최소 5.5초 |

## 3. 카드 종류 (`type`)

| type | 카드 | 입력 필드 | 그리는 법 |
|---|---|---|---|
| rows | 차량 정보 | rows [이름, 값] | 줄 82, 이름 36 회색 왼쪽, 값 40 Bold 오른쪽 |
| grid | 옵션 정보 | items [이름, 1/0] | 3열 칸 96. 장착은 ✓ 3D 아이콘을 쓰고, 미장착은 회색 칸에 「없음」 |
| bars | 추가 옵션 | bars [분류, 개수] | 분류별 노랑 막대와 개수 세기 |
| status | 보험 이력 | rows [이름, 값, ok/info] | ok는 ✓ 아이콘, info는 회색 ! |
| inspection | 성능 점검 | rows, data_pending | 위에서 본 차 윤곽과 부위 칸. 기록부 데이터를 연결하면 교환·판금 부위를 칠한다 |
| tiles | 차량 특징 | tiles [사진, 이름, 자르기 비율] | 2×2 사진 칸. 아래쪽을 어둡게 하고 흰 이름을 얹는다 |
| seller | 판매자 설명 | sub, stats, rows, quote | 판매중·판매완료 칸, 단지·위치, 설명 인용 |
| warranty | 보증 현황 | items [이름, 상태, 총기간] | 만료면 막대를 회색으로 둔다 |
| price | 가격 | price_manwon, save_pct | 큰 숫자 132 Black과 「신차 대비」 노랑 칩 |
| views3 | 3면 보기 | views [사진, 이름] | 정면·대각·후면 사진 3칸 |

## 4. 사실 규칙 (지키지 않으면 전달하지 않는다)

1. 입력 JSON에 있는 값만 쓴다. 숫자와 평가는 새로 만들지 않는다.
2. 「무사고」라는 낱말은 쓰지 않는다. 보험 카드에는 「보험 기록이 없어도 사고가 없었다는 뜻은 아니에요」를 늘 붙인다.
3. 차량번호, 전화번호, 원본 주소는 넣지 않는다. 번호판은 가리지 않는다(반사기 원칙).
4. 데이터가 아직 연결되지 않은 카드는 `data_pending: true`로 표시하고, 화면 아래 회색 주석으로 그 사실을 밝힌다.
5. 사진은 자르기, 확대, 흐림만 한다. 배경을 바꾸거나 보정하지 않는다.

## 5. 소리

- 배경음은 `bobae_showroom_v1.mp3`이며 0.22배로 줄여서 깐다.
- 효과음은 `whoosh.wav`(카드 등장, 0.55배)와 `pop.wav`(행 등장, 처음 3개만, 0.35배)를 쓴다.
- 최종 음량은 −14 LUFS ±1, 최대 −1.5 dBTP다(loudnorm).

## 6. 실행

```bash
python3 scripts/shortform/card_info/render_cards.py samples/g400d_cards.json \
  --photos <사진폴더(p01.png…)> --out <출력폴더> \
  --assets <public/assets/shortform 경로(sfx·bgm 원본이 있는 곳)> [--only insurance,options] [--reel]
```

- 컷 하나는 약 10초 안에 만들어진다. 10컷은 약 1분 50초 걸린다.
- `--reel`을 주면 모든 카드를 이어 붙인 한 편을 함께 만든다.

## 7. 데이터 연결 (다음 단계)

- 차란차 상세 정보는 화면이 불러올 때 `svc.charancha.com` 쪽 화면 데이터로 온다. 이번에는 공개 화면에 보이는 글자만 읽었다.
  - 직접 요청은 막혀 있어 쓰지 않았다.
  - 성능점검 상세(부위)는 새 창으로 열려서 읽지 못했다.
- 정식 연결은 보배드림 매물 API(Laravel)가 이 JSON 모양을 그대로 주도록 한다. 그러면 렌더러는 고칠 필요가 없다.
