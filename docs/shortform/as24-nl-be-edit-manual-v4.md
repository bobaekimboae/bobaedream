# AS24 네덜란드·벨기에 편집 완전 구현 매뉴얼 v4 (2026-11-09, 100+100편 재조사)

- 범위: 오토스카우트24 네덜란드(NL) 100편 + 벨기에(BE) 100편. 이전에 사람이 본 50+50편(`as24-caption-rules-v2.md`)에 새로 고른 50+50편(무작위, seed 1109)을 더했다.
- 분석 전용이다. 원본 영상·음악·목소리·효과음은 쓰지 않는다. 보배드림은 자체 효과음 팩만 쓴다.
- 이 문서가 NL·BE 편집의 최신 기준이다. 앞선 문서(`as24-sfx-rules-v1.md`, `as24-caption-rules-v2.md`, `as24-edit-skeleton-v3.md`)와 다른 곳은 이 문서를 따른다(§7 바로잡은 것).

## 2. 효과음 — 어디에 넣나 (순간별 비율, 오판정 보정값)
| 순간 | NL | BE |
|---|---|---|
| 칩·이름표가 뜰 때 | **약 43%** | 약 23% |
| 큰 숫자가 뜰 때 | **약 45%** | 약 15% |
| 첫 화면(0초 제목) | **약 46%** | 약 13% |
| 컷 | 약 12% | 약 6% |
| 끝 로고 | 약 11% | 약 9% |
| 말 따라가기 노랑 낱말 | 기준선 수준(따로 안 넣음) | 기준선 수준 |
| 아무 시각(대조) | 약 3% | 약 3% |

- 시작 시각: 효과음은 칩이 **처음 보이는 바로 그 순간** 시작한다(추적기 기준 중간값 +0.05초, 가운데 절반 −0.03~+0.13초. 추적기가 0.1초 단위라 「같은 순간 ±0.1초」로 본다).
- 영상마다 차이가 크다: NL 영상별 칩 효과음 비율은 10%(하위) ~ 65%(상위), 중간 35%(보정 전).
- 음악과의 관계: BE에서 음악 없는 29편은 영상당 3번, 음악 있는 71편은 1번. NL에서 음악 있는 6편도 1번. → **음악을 깔면 효과음을 줄인다**는 규칙이 두 나라 모두 맞다.
- 칩 추적기가 못 잡는 순간의 효과음: 소리만으로 영상 전체를 훑었을 때 칩·컷과 떨어진 곳의 후보는 사람 확인에서 NL 4/20, BE 2/20만 진짜였다. 효과음은 거의 다 **화면 편집물에 붙는다**.

## 7. 바로잡은 것 (앞선 문서와 다른 곳)
1. **벨기에 말 자막은 한 가지가 아니다.** v2는 「보통 글씨 + 그림자」만 적었지만, 새 50편 중 21편은 NL과 같은 「대문자 + 테두리」였다. 우리 벨기에판은 그림자형을 쓴다(벨기에다운 쪽).
2. **NL 첫 화면에도 효과음이 있다**(약 46%). 이전 규칙 「첫 화면에는 넣지 않는다」를 네덜란드판만 바꿨다.
3. **효과음 간격**은 실제로 짧아도 약 1초다. 최소 0.6초 → 1.0초.
4. **BE 칩 기울기는 늘 반시계**다. 이전 시안은 좌우를 번갈아 기울였다.
5. **BE도 숫자 칩이 떠 있으면 말 자막을 숨긴다**(9편).
6. **자막 높이**: NL 65% → 62%, BE 67% → 64%(100편 중간값 기준).
7. NL 칩 효과음 비율은 39%(소표본) → 약 43%(100편, 보정값). 「약 40%」 규칙은 그대로 맞다.
8. BE 띠 효과음 22% → 약 23%, 음악 없는 BE는 영상당 3번으로 NL에 가깝다.

## 8. 아직 못 본 것
- 넘김 효과(나눔 화면 등)와 등장 움직임은 정지 화면 16장으로 본 것이라 일부만 잡혔다. 보배드림 벨기에판에는 아직 나눔 화면을 넣지 않았다.
- 효과음 세기는 상대값(NL보다 BE가 약 5dB 작음)만 쟀다. 절대 크기는 우리 −6dB를 유지한다.
- 칩 종류 자동 분류(67%)가 약해 종류별 효과음 비율은 확률 가중 추정이다(±5%p 안팎으로 봄).
- 다시 돌리는 법(노트북): `sfxscore.py`(소리 수치) → 작업 폴더 `rs/run200.py`(순간별 판정) → `scan.py`(전체 훑기). 판정기 학습 자료는 `labels.json`(사람 판정 621곳).

### 9-2. 옵션·기능 ↔ 컷 맞추기
1. 옵션 칩은 **그 부위가 보이는 컷 위에서만** 뜬다(옵션표의 `parts`와 컷 라벨 `part`가 같아야 함).
2. 그 부위 컷이 영상에 없으면 칩도 대사도 넣지 않는다(화면에 안 보이는 옵션은 말하지 않음). 실내 화면 기능(내비·통풍 등)만 계기판·화면·핸들 컷으로 대신할 수 있다.
3. 한 부위 컷은 한 옵션에만 쓴다. 겹치면 다음 순위 부위로 넘기고, 남는 부위가 없으면 그 옵션은 뺀다.
4. 옵션은 매물 옵션표에 있는 것만 쓴다. 지어내지 않는다.
5. 코드: `scripts/shortform/auto/auto_edit.py`(옵션 고르기 · 부위 배정), `sag_reel_v1.py` `chip_kind`(칩 종류).

### 9-9. 자막·음성 빠짐 — 원인과 재발 방지 (2026-11-10)
**원인(조사 결과)**

| 증상 | 원인 | 이전 수치 |
|---|---|---|
| 말은 나오는데 자막이 안 보임 | 칩이 뜨면 무조건 말 자막을 숨김(NL 큰 숫자·옵션 ✓ 칩이 자막 자리, BE 숫자 칩) — 칩 내용이 말과 달라도 숨김. 「HUD ✓」가 뜨는 동안 「헤드업 디스플레이가…」 자막이 사라짐 | 말하는 시간 중 자막 없음: GLE NL 6.6초 · BE 10.0초, 차란차 BE 6.0~8.1초(말의 약 35~45%) |
| 짧은 말이 통째로 안 보임 | 벨기에판 「컷 뒤 0.3초 자막 비우기」가 1초 안팎 짧은 구절에도 걸림 | 위 수치에 포함 |
| 끝 문장 소리·자막이 잘림 | 목소리 후처리에서 loudnorm을 섞기 전에 걸어 끝 3초가 잘림(앞서 고침) | 현재 18편 낱말 검사 0곳 |
| 장면·자막이 엉뚱한 곳 | 원본 fps 25를 30으로 계산(§9-8) | — |

**재발 방지(가변 규칙 `auto_edit_rules.json` → `captions`, 렌더러는 값만 읽음)**
- `hide_mode: related` — 칩이 지금 말과 **같은 내용(같은 숫자·같은 낱말)** 일 때만 자막을 칩으로 대신한다. 다른 내용이면 자막은 그대로 두고 칩을 자막 위로 올린다. (`always` = 원본처럼 숨김, `never` = 숨기지 않음)
- `cut_gap_min_phrase_s: 1.2` — 컷 뒤 비우기는 1.2초 이상 구절에만.
- `min_visible_ratio: 0.6` — 구절마다 말하는 동안 자막이 60% 이상 보여야 통과.
- `voice_check.min_word_db: -9` — 완성 영상 소리에서 낱말마다 원래 목소리보다 9dB 넘게 작아지거나 영상 끝에서 잘리면 실패.

**배포 전 필수 크로스체크(10배 강화 기준, `scripts/shortform/auto/crosscheck.py`)** — 2~9번 실패가 1건이라도 있으면 배포하지 않는다.

| 번호 | 항목 | 기준(규칙 위치) |
|---|---|---|
| 1 | 칩 ↔ 부위 | 칩이 뜬 순간 화면 부위가 그 구간 허용 부위 안(`parts_for_section`·옵션표) — 알림 |
| 2 | 장면 넘침 | 0곳(`shot_fit.check.max_overflow`) |
| 3 | 자막 빠짐 | 구절별 보임 ≥ 60%(`captions.min_visible_ratio`) |
| 4 | 음성 빠짐 | 낱말별 −9dB 이내·끝 잘림 없음(`captions.voice_check`) |
| 5 | 검은 화면 | 끝 화면 전 0.3초 넘는 검은 장면 없음(`crosscheck.black_*`) |
| 6 | 칩 색 | 민트 칩 없음 — 모든 칩 원본 노랑(`crosscheck.mint_px`) |
| 7 | 음량 | −14 ±1.5 LUFS, 최대 −1 dBTP(`crosscheck.lufs*`) |
| 8 | 길이 | 목소리 뒤 끝 화면 1.5~3.5초(`crosscheck.end_*`) |
| 9 | 규격 | 1080×1920 · 30fps · H.264 · AAC |
| 10 | 촬영 필요 | 원본에 없는 부위 목록 — 알림(`shot_fit.required_shots`) |

**18편 크로스체크 결과와 보완(2026-11-10, 2차)** — 18편 중 14편은 처음부터 2~9번 0건. 실패 7건을 원인별로 고쳤다.

| 실패 | 원인 | 보완(가변 규칙) |
|---|---|---|
| 칩 색 4건(GLE NL 42.8초, 차란차 04 BE 4.0초) | 검사 오탐: 실내 앰비언트 조명·파란 전시장 화면의 청록 번짐을 민트 칩으로 셈(화면에 민트 칩 없음, 캡처로 확인) | 민트 칩 판정을 칩 바탕색 #00FFD0 ±18 안의 화소로만(`crosscheck.mint_rgb`·`mint_tol`). 오탐 4곳 → 0 |
| 자막 빠짐 1건(GLE NL 「열선 시트는…」 59%) | 같은 말의 칩 「열선 시트」가 자막 자리에서 자막을 대신한 1.3초를 빠짐으로 셈 | 같은 말을 보여 주는 칩이 떠 있던 시간은 보임으로 센다(`match.json` `visible`), 자막만 보인 비율은 `caption_only`로 따로 남김 |

**포인트칩 대사 자막 (2026-11-10, 3차 — 사용자 「포인트칩 있는 대사는 자막에 안 나온다」)**
- 원인: `hide_mode: related`는 칩이 말과 같은 내용이면 칩이 자막을 대신하게 했다(원본 NL 방식). 그래서 칩이 뜬 순간 그 낱말이 자막에서 빠졌다. 계획 파일로 전수조사해 보니 네덜란드판 ✓ 목록 칩에서 생겼다(GLE NL: 어라운드뷰 · 통풍 시트 · 열선 시트 · 메모리 시트). 칩이 말과 다른 내용인데도 `never`가 자막을 숨기던 렌더러 버그도 있었다.
- 규칙: `captions.hide_mode: never`. 자막은 늘 보이고, 자막 자리 칩은 자막 바로 위로 올린다. 렌더러 버그도 고쳤다.
- 검사: 칩마다 칩이 뜬 1.3초(`captions.chip_check_s`) 동안 자막이 보인 비율을 `match.json` `chips[].cap_shown`에 남기고, 60% 미만이면 크로스체크 3번(자막 빠짐) 실패. `never`에서는 구절 비율도 자막만 센다(`caption_only`).
