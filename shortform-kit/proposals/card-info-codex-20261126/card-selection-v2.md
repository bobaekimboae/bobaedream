# 카드정보 2차 제안 적용 규칙 v0.2

작성: 서울오토갤러리 자동 영상 제작 코덱스 마스터 · 2026-11-26

근거: [사용자 2차 제안](https://app.notion.com/p/424ee9c4b606809c9f29da537eba5c20). 이 문서는 같은 폴더 README.ko.md의 1차 제안과 충돌하는 **카드 선택·삽입 규칙**을 대체한다. 운영 렌더러 연결·국토부 API 연동·실제 MP4 제작 완료를 뜻하지 않는다.

## 총괄 v3와의 관계

작업 도중 등록된 [클로드 총괄 v3](https://app.notion.com/p/424ee9c4b60681cc9f4afba37f54a0c1)를 함께 읽었다. 이 패킷은 별도 디자인 정본이 아니라 선택·출처 검수의 보완 의견이다. 총괄 v3의 밝은 카드·모션·음성 규격을 대체하지 않는다.

국토부 원문이 없는 **공개자료 기반 훈련 타임라인**은 출처와 “국토부 원문 미확보”를 명시하면 비교 실험할 수 있다. 이 문서의 G400d 3종 출력 예는 **공식 국토부 이력으로 표현하는 출력**을 검사하는 경우다. v3의 혼합 출처 훈련 타임라인을 일괄 금지한다는 뜻은 아니다. 두 출력 범위를 메타데이터에 구분한다.

requested_type_ids는 딜러가 매번 손으로 고르는 값일 필요가 없다. 자동 선택 정책이나 프리셋이 먼저 생성할 수 있다. 다만 자료가 있는 앞 N장을 고르기만 하면 알려진 보험피해나 수리 내역이 예산 때문에 빠질 수 있으므로, 중요 사실을 선정하는 정책과 선정 후 표시 순서를 분리하는 개선을 제안한다. 국토부 자료 미확보·전부 미확인일 때 최소 한 장을 강제로 채우는 규칙도 예외 처리가 필요하다.

## 1. 확정된 변경

- 유형은 기존 7종 + 차량이력 타임라인 = **8종**이다. 8종은 라이브러리의 종류 수이며 한 편의 필수 카드 수가 아니다.
- 선택한 기본 카드들의 상대 순서는 **차량 기본정보 → 성능점검 → 보험이력 → 차량이력 타임라인**이다. 중간 카드가 빠져도 남은 순서를 유지한다.
- 옵션정보·추가옵션·차량특징·판매자 설명도 매물별로 선택한다. 이 네 유형을 선택된 기본 카드 뒤에 배치하는 것은 이번 계약의 기본 제안이며 사용자 확정 배치로 오해하지 않는다.
- 한 종류만 넣을 수 있고 여러 종류를 넣을 수 있다. 카드 기능을 끄거나 선택하지 않거나 사용 가능한 자료가 없으면 0종이다. 이때 카드 화면을 억지로 만들지 않고 생략 이유를 기록한다.
- 이 v2 모드에서 차량 기본정보를 무조건 두 번째 컷에 넣던 조건은 적용하지 않는다. 기존 v1 프리셋 자체를 바꾸는 것은 아니다. 선택된 카드 중 먼저 나온다는 뜻과 영상의 첫 장면에 반드시 나온다는 뜻을 구분한다.
- 자료가 있어도 요청되지 않은 카드가 자동으로 모두 삽입되면 안 된다. 요청된 카드도 근거가 없으면 생략하고 다른 카드로 임의 대체하지 않는다.
- 선택하지 않은 카드가 있다고 해서 이미 파악된 수리·안전 주의사항을 전체 영상 QA에서 지우지 않는다. 이력 카드의 유무와 중요한 사실의 고지 여부를 별도로 검수한다.

## 3. 타임라인의 출처와 날짜

[국토부·한국교통안전공단 디지털서비스 안내](https://openservice.go.kr/vehHistInq)는 자동차365의 검사·정비·의무보험 가입·체납·압류 등 통합이력을 안내한다. [한국교통안전공단 안내](https://main.kotsa.or.kr/portal/contents.do?menuCode=04040300)는 본인·소유자동의·미동의·매매용 조회에 따라 제공 범위가 다름을 설명한다. 이 일반 서비스 설명을 특정 매물의 이력이 확보된 증거로 사용하지 않는다.

- `MOLIT_TS_CAR365`는 이 계약의 공급자 구분값이다. 실제 신청 API 이름·주소나 이미 연결된 서버 이름이라고 주장하지 않는다.
- 사건별 source_provider·source_record_id·source_url·source_as_of·observed_at·access_basis_ref를 둔다. 접근 근거 참조에는 인증 토큰·소유자 개인정보를 넣지 않는다.
- **의무보험 가입 정보와 보험사고 수리비는 별개다.** 차란차/카히스토리의 보험자료를 국토부 이력으로 바꾸지 않는다.
- 발생일과 문서 발급일·조회일을 구분한다. 월까지만 있으면 월까지만 표시한다. 날짜가 없는 변경 횟수에서 날짜를 생성하지 않는다.
- 정확한 날짜끼리는 시간순으로 표시한다. 같은 달·연도 안에서 순서를 모르는 사건은 임의의 일자를 붙여 순서를 만들지 않는다.
- 공급자와 원본 기록 ID가 같은 중복만 기계적으로 묶는다. 여러 공급자의 같은 사건으로 보이는 기록은 근거 없이 합치거나 횟수를 더하지 않는다.
- 보험 카드에서 이미 말한 같은 사건을 타임라인에서 다시 길게 발화하지 않는다. 원본 기록은 유지하고 표시·대사의 중복만 줄인다.
- 압류·저당 등 과거 사건은 현재 효력을 자동 뜻하지 않는다. 조회 범위·현재 상태가 미확인이면 없음·해제 완료로 표시하지 않는다.

## 4. G400d로 만드는 실제 제작 입력 예

이번 패킷에는 국토부·TS의 이 매물 단위 응답이 없다. 따라서 기본 네 유형을 요청하더라도 출력 계획은 **차량 기본정보 → 성능점검 → 보험이력**, 타임라인은 출처 미확보로 생략한다. 이는 다른 시스템에 API 연결이 전혀 없다는 뜻이 아니라 이 검수 패킷에서 응답을 검증하지 못했다는 뜻이다.

비교·설계용으로 알고 있는 다음 사건은 `cross_source_reference_events`에만 둔다. 이 목록을 국토부 자료라고 제목 붙여 렌더하지 않는다.

| 날짜 | 사건 | 실제 근거 |
| --- | --- | --- |
| 2021.05.04 | 최초등록 | 차란차 보험이력 상세 |
| 2022.02.09 | 내차 보험피해 1회 · 수리·견적비 839,280원 | 차란차 보험이력 상세 |
| 2026.10.30 | 성능점검 · 33,288km | 성능점검기록부 |
| 2026.11.10 | 소유자 변경 1회 | 차란차 보험이력 상세 |

[보험 이력 원문](https://charancha.com/insurance-history?carId=01a1cd73-fe70-7cc7-b7a7-1cb36fa211a8)의 최초등록·소유변경 날짜와 금액을 2차 작업에서도 다시 읽어 대조했다. 보험 자료일은 2026.11.12다. 점검 원문과 그 밖의 기존 사실은 source-review-addendum.md의 확인 시점·출처를 따른다.

시안별 비교는 ① 보험이력 한 종류만 ② 기본 네 유형 요청·타임라인 근거 없어서 세 종류 출력 ③ 옵션정보만 ④ 카드 끔 네 가지로 한다. 옵션정보 시안은 실제 선택 상태와 장착 근거를 확인한 항목만 사용한다. 기본 카드 누락분을 0건·빈 카드·다른 차량 데이터로 보충하지 않는다.

## 5. 자동화 순서와 검수

입력 revision 고정 → card mode·선택 유형 확인 → 유형별 근거·출처 자격 확인 → 생략 이유 기록 → 기본 상대 순서 정렬 → 중복 발화 제거 → 승인 대사 → ElevenLabs 실제 타임스탬프 → 카드 길이·페이지 분리 → 기존 렌더러 → 실제 영상·음성·모바일 검수.

한 유형이 두 페이지로 나뉠 수 있으므로 유형 수와 실제 화면 수를 따로 센다. 카드 시간은 기존 개별 시간표를 초안으로만 사용하고, 실제 음성 길이+0.25초와 읽기 시간을 충족한다. 일정한 2초에 맞추려고 문장을 자르거나 빨리 읽지 않는다.

`card-selection-v2.json`은 입력 계약·8종 대응·사건 속성·G400d 선택 예다. `check_v2_policy.mjs`는 선언된 상대 순서에 대한 참조 계획 검사다. 기본 6개 사례와 가능한 256개 유형 조합을 검사하고 G400d 국토부 타임라인이 제외되는지 확인한다. **운영 제작기의 선택기·API·렌더러를 실행한 시험은 아니다.**

검수 입력·출력에는 `selection_version`, `requested_type_ids`, `selected_type_ids`, `skipped[].reason`, `source_snapshot_hash`, `script_hash`, 실제 음성/자막 타임스탬프와 MP4 QA를 함께 보관한다. 웹·모바일 UI는 Nuxt/Vue를 유지하고 권한·이력 제공 범위·영속화는 Laravel이 담당한다. 이 문서로 업무 로직이나 패키지 버전을 교체하지 않는다.

## 6. 클로드 시안 1·2에 전달할 제작 기준

- 각각 기본 네 유형을 전부 강제 삽입하는 예제를 중지하고 위 네 가지 선택 사례를 같은 사실·대사로 비교한다.
- 국토부 이력은 응답·제공 범위를 확인한 뒤 실제 카드 샘플을 만든다. 현재 보험자료로 출처만 갈아 끼운 카드는 만들지 않는다.
- 새 규칙은 v2 preset/selection_version으로 분리한다. 기존 v1 라이브러리 훈련본과 v2 판매용 계획을 혼동하지 않는다.
- 색·폰트·아이콘 원본은 기존 확정 규칙을 유지한다. 누락 카드가 생겨도 남은 컷·음성·자막을 다시 정렬하고 빈 시간을 남기지 않는다.
- 현재 매물의 판매 상태를 공개 배포 직전에 재확인한다. 판매완료면 과거 매물 훈련 예시로 구분하고 실제 판매 중인 광고처럼 게시하지 않는다.

기존 1차 사실 오류 12개 검수 사례도 계속 적용한다. 이번 완료 범위는 선택 계약·자료 원장·제작 인수인계와 참조 계획 검증이다.
