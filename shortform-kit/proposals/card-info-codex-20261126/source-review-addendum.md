## 반드시 구분할 다섯 가지

1. **수리·견적비 ≠ 지급 보험금.** 원문은 대차료 등과 과실상계 때문에 다를 수 있다고 안내한다. F26의 금액을 보험금이라고 말하면 실패다.
2. **보험가액 ≠ 판매가격.** 보험 화면의 7,230만원을 차량 판매가나 신차가로 넣지 않는다. 판매가는 매물 원장의 13,490만원이다.
3. **사고이력 없음 ≠ 수리 없음.** 기록부의 두 판정을 함께 보존한다. 반대로 외판 W 하나만으로 골격사고·사고차를 단정하지 않는다. A/B/C 부위 랭크는 차량의 전체 품질 등급이 아니다.
4. **과거 리콜 기록 ≠ 현재 상태.** 2026-10-30의 해당·미이행과 2026-11-26 열람을 다른 필드로 둔다. 현재 완료 증빙이 없으면 현재 미이행이나 완료로 생성하지 않는다.
5. **시세 위젯 숫자 ≠ 유효한 비교 집단.** 10,000만원이 반복되는 범위만으로 저렴·고가·상위15%를 판정하지 않는다. 비교 모델·표본 수·기준일·산식을 확보하기 전 시세 비교 카드는 보류한다.

## 시안 1·2에서 시험할 편집 방법

### 보험 카드: 의미를 보존하며 두 장으로 분리

- 첫 장: 내차 피해 **1회**, 발생일 **2022.02.09**. 대사: “보험 이력에는 내 차 피해가 한 번 기재돼 있습니다.”
- 다음 장: **수리·견적비 839,280원**. 대사: “기재된 수리·견적비는 팔십삼만 구천이백팔십 원입니다.”
- 작은 주석으로 “지급 보험금과 다를 수 있음 / 보험자료 2026.11.12”를 붙인다. 주석이 휴대폰에서 읽히지 않으면 별도 화면으로 분리한다.
- 주석까지 음성으로 말한 경우 해당 문장도 자막에 모두 넣는다. 문장 길이를 맞추려고 음성을 자르지 않는다.

### 성능 카드: 좋은 판정과 수리 내역을 같은 흐름에 표시

- 첫 장: “기록상 사고이력 없음 / 단순수리 있음 / 기록일 2026.10.30”.
- 다음 장: 트렁크리드 W(판금 또는 용접), 운전석 앞문·쿼터 도장수리를 부위별로 보여준다. W를 교환 아이콘으로 치환하지 않는다.
- 차종별 공식 손상도 자산이 있으면 부위 지도에 연결하되, 동일 실차의 수리 사진이 없는 경우 사진이 있는 것처럼 만들지 않는다.
- 사고이력 없음만 초록 배지로 크게 남기고 수리 내역을 숨기는 화면은 반려한다.

### 자료 날짜를 분리하는 디자인

카드 하단은 “자료 기준 2026.10.30 / 확인 2026.11.26”처럼 두 시간을 구분한다. 최신 매물 주행거리 33,475km와 점검 당시 33,288km를 한 날짜의 수치처럼 겹치지 않는다. 기준일 누락을 확인일로 자동 메우지 않는다.

이 세 가지는 기존 카드 유형의 세부 연출이다. 임의의 신규 기법 ID를 운영 사전에 등록한 것이 아니다.

[벨기에 실제 매물](https://www.autoscout24.be/nl/aanbod/audi-a3-a3-sportback-30-tfsi-advanced-benzine-cat_ma9mo1624-b29421fc-79ca-48ed-827c-0f237c62d7bd)의 기본정보 → 차량이력 → 기술제원 → 에너지소비 → 장비 → 색상/내장 → 설명 → 판매자 분류를 확인했다. 카드에는 같은 종류의 사실끼리 묶고 숫자·단위를 우선 읽게 하는 정보 위계를 참고한다. 릴스의 픽셀·초수·효과음을 동일하게 측정했다는 뜻은 아니다. 확정된 be_locked_rules·사진형 두 번째 카드 고정·브랜드 색상·폰트는 이 보완으로 변경하지 않는다.

## 제작·검수 순서

1. 원장 revision과 fact_id·단위·출처 URL·자료일을 고정한다. 이번 시트에 이미 있는 F01~F32는 유지하고 F33~F36만 확장한다.
2. 승인 대사를 사실과 연결한다. 카드 요약과 전체 음성 자막은 구분한다. 음성의 모든 단어를 의미 단위 1~2줄 자막으로 보존한다.
3. ElevenLabs 최종 음성을 만들고 실제 타임스탬프로 카드 길이를 정한다. 기존 매뉴얼의 음성 길이+0.25초와 읽기 시험을 충족하고 상한 초과 시 분리한다. 이 문서의 대사 시간은 실측하지 않았다.
4. 시안 1·2는 같은 사실·대사·음성·정보 순서를 사용한다. 확정 규칙 안에서 레이아웃·모션 차이만 비교한다.
5. pre/post 검수에서 아래 회귀 사례를 연결한다. 사실 검사 통과가 모바일 가독성·음성 청취 통과를 대신하지 않는다.
6. MP4, 대사, alignment, timeline, used_techniques, 원장/폰트/자산 해시, 렌더러 버전, 제작시간, 수동 개입 횟수, QA 보고서를 같은 회차에 저장한다.

## 회귀 사례와 완료의 경계

source-review-cases.json은 허용 문구와 반려 문구를 정리한 **검수 입력 사례**다. 실제 제작기의 차단 기능을 구현하거나 통과 시험한 결과가 아니다. 기존 파이프라인 담당이 해당 입력으로 검수기를 실행하고 기대 결과와 비교해야 한다. 기존 오디오 채널·딜레이·독립 청취 검사는 그대로 유지한다.

이 변경은 문서·검수 데이터 보완이다. Nuxt 사용자 화면, Laravel 업무 로직, FFmpeg 렌더러, 잠금 파일, 운영 API·배포를 변경하지 않는다. 현재 노션에는 다른 담당의 샘플 제작 기록이 있으나 이번 보완 담당은 MP4를 직접 재생하지 않았으므로 영상 점수를 매기지 않는다.
