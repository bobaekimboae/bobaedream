# 카드 정보 숏폼 제작 매뉴얼 v1 (클로드 시안 1)

매물 한 대의 정보를 **카드 7장 + 자막**으로 요약하는 독립 컷 숏폼. 엔카처럼 화면을 하나씩 열지 않고 숏폼 한 편으로 성능·보험·옵션·판매자까지 본다.
어떤 에이전트든 **같은 JSON → 같은 영상**이 나오게 하는 것이 원칙이다.

## 1. 제작 순서 (자동)
1. `python3 fetch_charancha.py <차란차 매물 URL> src` — 원자료 JSON 8종 + 사진 PNG
2. 원자료 → `data/<차량>.json` 작성 (아래 3번 매핑표, 사실만)
3. `bash build.sh data/<차량>.json out/<차량>` — 미리보기 PNG 9장 + 통합본 `card_all.mp4` + 유형별 `card_0N_<type>.mp4`
4. 미리보기 PNG로 검수(4번 체크리스트) 후 전달

필요: Node + Playwright(Chromium), ffmpeg, Python3(Pillow), 글꼴 Pretendard 1.3.9(`fonts/`에 Medium·Bold·ExtraBold·Black woff2, `npm pack pretendard@1.3.9`로 받음).

## 3. 카드 7종과 데이터 매핑 (사실만, 지어내지 않음)
| 순서 | type | 카드 | 원자료 | 핵심 문구 규칙 |
|---|---|---|---|---|
| 1 | inspection | 성능 점검 | 성능·상태점검기록부(체크 항목) | 사고이력 유무를 크게. 단순수리·누유·리콜 미이행은 행으로, 리콜 미이행은 빨강 |
| 2 | insurance | 보험 이력 | summary-info.insurance | 내차피해 건수가 1 이상이면 주의색. 숫자 칸 3개(내차·타차·소유자 변경) |
| 3 | vehicle | 차량 정보 | basic-info + new-car-comparison | 6칸 격자 + 신차가 대비 절감액(검정 띠, 노랑 숫자) |
| 4 | options | 옵션 정보 | main-options 12종 | `12개 중 N개`, 없는 옵션은 점선 칩 + ✕ |
| 5 | extra_options | 추가 옵션 | choice-options(유료 선택옵션) → 없으면 group-options 장착 품목 | 그룹별 막대(장착/전체) + 눈에 띄는 품목 4개 |
| 6 | features | 차량 특징 | 제조사 공개 제원(추후 JATO API) | 엔진·구동·핵심 기능 4행 + 엔진룸 사진 |
| 7 | seller | 판매자 설명 | basic-info.description | **설명이 없으면 「대체 카드」**: 판매 실적(누적·판매중) + 성능 보증 |

- 데이터가 없는 칸은 숨기지 말고 `미공개`·`등록 없음`으로 적는다(수리비 금액 미공개 등).
- 차량번호·전화번호는 카드·자막에 쓰지 않는다. 다른 회사 로고가 큰 화면에 나오지 않게 인트로 사진은 아래쪽으로 잘라 쓴다(`background-size 150% · position 50% 92%`).
- 가격은 공개(2026-11-10 결정).

## 4. 검수 체크리스트
1. 자막이 한 줄인가(18자 이내), 핵심어만 노랑인가
2. 카드 숫자·문구가 원자료와 같은가(성능기록부 번호·점검일 포함)
3. 카드가 세로 가운데이고 자막과 겹치지 않는가
4. 대체 카드 표시(판매자 설명 없음)가 정확한가
5. 영상 31.2초, 1080×1920, 소리 있음(최대 −12dB 안팎)

## 5. 파일
- `template/card.html` — 카드 HTML/CSS + `setup(장면)`·`render(t)` (시간을 넣으면 같은 프레임이 나오는 결정적 렌더)
- `render.js` — Playwright로 프레임을 찍어 ffmpeg로 이어 붙임 (`preview` / `each` / `all`)
- `mux.py` — 효과음 합성, `build.sh` — 일괄 제작, `fetch_charancha.py` — 매물 원자료 받기
- `data/g400d.json` — 샘플(차란차 벤츠 G400d)
- 서비스 이식: 같은 템플릿을 Nuxt 4 컴포넌트(Vue)로 옮기고, Laravel 큐 작업자가 이 렌더러를 돌리는 구조로 간다(리액트 사용 안 함).

## v2 (2026-11-26, 2차 제안 반영)

**2차 제안 원문 요지**: 엔카 매물정보가 있는 카드는 엔카 기본 순서(차량 기본정보 → 성능 점검 → 보험 이력 → 차량 이력 타임라인)로. 신규 = 국토부 차량이력 타임라인. 카드는 필수가 아니라 **매물에 따라 1장부터 여러 장까지** 차량 편집에 포함.

### 순서 (data.meta.order)
`vehicle → inspection → insurance → timeline → options → extra_options → features → seller`

### 매물별 선택 (data.meta.presets)
| 프리셋 | 카드 | 인트로/아웃트로 | 용도 | 길이 |
|---|---|---|---|---|
| full | 7장 | 있음 | 카드만으로 된 단독 숏폼 | 31.2초 |
| encar4 | 차량 정보·성능·보험·타임라인 | 없음 | 차량 편집 안에 끼워 넣는 독립 컷 | 14.4초 |
| single_inspection | 성능 점검 1장 | 없음 | 1장 삽입 | 3.6초 |
| single_timeline | 타임라인 1장 | 없음 | 1장 삽입 | 3.6초 |

- 명령: `bash build.sh data/<차>.json out/<폴더> [프리셋...]` (생략 시 전부). `node render.js <data> <out> all <프리셋>`.
- `available:false` 카드는 프리셋에 있어도 자동 생략. 예: 이 매물은 선택옵션(유료) 등록이 없어 **추가 옵션 카드 생략** (전체 장착 품목 수로 대체 금지).
- 진행 표시(01/04)와 인트로 「{n}장 카드로」는 실제 고른 장수로 자동.

### 차량 이력 타임라인 카드 (timeline)
- 데이터: `timeline:[{date|null, t, s, gap?, point?}]`. date가 null이면 「날짜 미공개」(지어내지 않음).
- 국토부 자동차 이력(등록원부)·차란차 registration-info(로그인 필요)를 연동하면 등록·이전·검사 날짜가 자동으로 채워진다. 이번 샘플은 공개 자료만: 2021.05 최초 등록 / 소유자 변경 1회(날짜 미공개) / 2026.10.30 점검 33,288km / 2026.11.26 매물 33,475km → 「점검 이후 +187km」.

### v1 → v2 고친 것 (다른 에이전트 평가 반영)
1. 판정 색(초록·주황·빨강) 폐지 → 노랑 한 색. 확인할 값은 노랑 형광 밑줄.
2. 숫자 카운트업 제거(중간 가짜 숫자 노출 금지) → 최종값 페이드.
3. 「저렴」「↓」 평가 낱말 제거 → 「차이 2,570만원」 중립 표기, 출처(차란차 신차 비교) 명시.
4. 리콜: 「미이행」 단정 → 「리콜(점검일 기록) 대상·미이행」 + 「현재 이행 여부는 제조사 확인 필요」.
5. 성능 점검에 점검자 의견(운전석 앞문·쿼터 도장) 추가, 행 4줄 이하.
6. 판매자 설명이 비면 「판매자 정보」 카드(실적·보증 사실).
