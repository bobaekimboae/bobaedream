# PR #1102 실사용 적합성 검증 — 2026-11-01 (한국 시간)

**판정: 병합 보류.** 개선 코드는 기존 `shootkit-capture-checks` 브랜치에 반영한다. Android/iPhone 실기, 전체 RAM, 배터리·발열, 실제 이동통신망 최초 다운로드를 확인하지 못했으며, 심한 아래쪽 잘림에서 차량 탐지가 부족하다. GitHub의 `mergeable: true`는 충돌 여부일 뿐 이 판정을 바꾸지 않는다. 배포하지 않았다.

검증 시작 기준: `8053859e7b8819bb07f996f41b42bff9966d1d21`. 기존 보고서 `reports/pr-1102.md`의 7개 항목과 10/17 원거리 결과는 **과거 결과**이며 이번 시험으로 대체하거나 같은 표본인 것처럼 비교하지 않는다.

## 변경과 근거

- 위치 모델과 CLIP 칸 검사 모두 Worker에서 직렬 실행한다. 모델 종류가 바뀔 때 기존 Worker를 종료해 두 모델이 함께 상주하지 않도록 한다. 한 번에 추론 1건, 카메라 프레임은 대기시키지 않고 버리며 사진 검사는 최신 1건만 대기시킨다. 빠른 연속 촬영의 모든 사진을 검사했다는 보장은 하지 않는다.
- 동의 즉시 약 90MB CLIP까지 미리 받던 동작을 제거했다. 위치 안내에는 YOLOS만, 촬영 후 검사에 CLIP을 준비한다. 모델 준비와 실패가 셔터·저장·미리보기를 막지 않는다.
- 기존 앨범 분류 동의와 촬영 AI 동의를 분리했다. 기본 꺼짐, 켜기 전 별도 안내, 끄기 상태 지속. 끄기·화면 숨김·촬영 화면 해제 시 worker 종료와 미완료 작업 취소. 화면 숨김에는 카메라도 중지하며 복귀 시 다시 요청한다.
- 단일 WASM 스레드, 재사용 캔버스, RGBA 버퍼 전송을 사용한다. JPEG 인코딩→Image 재해독을 위치 추론에서 제거했다. 입력 최대 448px, 전처리 짧은 변 320px / 긴 변 최대 448px. 기존의 320px JPEG는 전처리 과정에서 짧은 변 512px로 재확대되고 있었다.
- 카메라 최대 30fps(희망 24fps), 위치 분석 최대 1fps. 느리면 추론 시간의 약 3배를 쉬되 최대 10초. 같은 판정 2회 확인 후 표시, 3.5초 지난 안내 삭제. 45초 작업 제한, 30초 유휴 worker 종료. 미탐지·다중 차량 불확실성은 초록색 성공으로 처리하지 않는다.
- 같은 차량의 중복 상자는 IoU로 구분하고 별개 차량이 비슷하게 크면 판단을 보류한다. 상하좌우 경계와 과도한 화면 점유를 검사한다. 실제 거리나 잘림을 단정하지 않고 “틀에 가까워요”라고 안내한다.
- Worker의 외부 CDN 실행 파일 import 실패를 재현했다. ONNX MJS/WASM을 버전에 맞춰 사이트에서 함께 제공하도록 수정했다. 모델 가중치는 고정 revision을 유지한다.
- 동의 문구는 위치 약 10MB, 칸 확인 약 90MB, 별도 실행 파일 다운로드를 구분한다. AI 분석은 사진을 전송하지 않는다. 일반 매물 업로드와 별개의 설명이다.
- 저장소 지침에 따라 Nuxt 4.6.2 / Vue 3.5.33 / TS 6.0.3 / pnpm 10.33.0으로 변경했다. Node 24.22.1에서 실행. `srcDir: "."`으로 기존 파일 구조를 유지하고 Nuxt 3의 배열 타입 검사 범위를 보존했다(`strict` 유지). npm lock을 pnpm lock으로 교체했다.

## 실행 환경과 성능

Linux x86_64, Chromium 134 / Playwright 1.51.1, 단일 WASM 스레드, cross-origin isolation 없음. 카메라 UI 시험은 실매물 사진을 넣은 합성 canvas 스트림이다. Android/iPhone을 에뮬레이션한 실기 시험이 아니다. 실제 기기 제어 도구·연결된 기기·adb·xcrun을 확보하지 못했다.

외부 모델 파일은 환경의 네트워크 프록시를 사용하는 curl로 중계·캐시했다. 브라우저 모델 캐시는 새 context로 시작했으나 중계 파일 캐시는 재사용했다. 따라서 아래 첫 추론은 **실제 LTE/5G 최초 다운로드 시간과 다르며**, 기존 보고서 21초와 직접 비교할 수 없다.

| 측정 | 결과 / 한계 |
|---|---|
| 최종 설정 첫 모델 준비+추론 | 약 1.864초, 로컬 파일 중계 환경 |
| 이후 118회 추론 중앙값 / P95 | 약 0.466초 / 0.516초 |
| 기본 전처리 512px 비교 | 동일 환경 별도 Worker, 사진 2장 × 원본/원거리 4회. 약 14.9~16.5초. 기존 PR 자체 UI의 전체 시간 측정은 아님 |
| 최종 YOLOS Worker JS heap used | 4,306,052 bytes (약 4.11 MiB) |
| Worker backing storage | 34,491,021 bytes (약 32.89 MiB) |
| Worker heap total / embedder heap | 6,488,064 / 634,552 bytes |
| 전체 프로세스 RSS / CPU 사용률 | 환경에서 유효한 읽기 불가. 0으로 반환된 probe는 null/미측정으로 기록 |
| 배터리·발열·실기 최대 RAM | 미측정. Worker V8 수치가 WASM·네이티브·카메라 전체 RAM을 뜻하지 않음 |
| 주 화면 long task 관측 | 모델 119회 처리 중 PerformanceObserver 기록 없음. 지속 촬영의 실기 프레임 속도 보장은 아님 |

WASM 파일은 약 21.6MB(빌드 gzip 약 5.17MB), 모델 가중치는 YOLOS 약 9.7MB와 CLIP 약 90MB다. **다운로드 크기와 실제 RAM은 다르다.** 동의 뒤에도 준비 지연, 오프라인, 브라우저 캐시 삭제, iOS 메모리 회수에 따른 재준비가 남는다.

CLIP Worker 측정도 전체 RAM을 포함하지 않는다. 실제 수치는 아래 CLIP 원자료에 별도로 남겼다.

원자료: [최종 119회](pr-1102-validation/benchmark-limited320.json), [512px 비교 4회](pr-1102-validation/benchmark-default512.json), [채택하지 않은 224px 시험](pr-1102-validation/benchmark-limited224.json).

### CLIP 칸 검사 실제 모델 시험

약 89,117,001 byte 모델을 사용하는 별도 Worker에서 동일 외관 사진을 2회 인식했다. 첫 준비+추론 2.867초, 다음 0.196초. 두 번 모두 외관 `front` 그룹 응답을 받았다(정확한 45° 각도 구분을 보장하지 않는다). [CLIP 결과/힙 측정](pr-1102-validation/benchmark-slot.json).

초기 시험 2회는 모델 바이트를 DevTools `route.fulfill`에 담아 보냈고, DevTools 로그의 `capacity=104857600` / `Connection closed, not enough capacity` 오류로 브라우저 연결이 종료됐다. 큰 모델의 base64 전달이 검증 도구 한도를 초과한 것이며 OOM 증거가 아니다. 모델 파일을 로컬 HTTP에서 스트리밍하도록 시험기를 고친 후 재시험에 성공했다. [해결된 시험기 오류 기록](pr-1102-validation/slot-failure.json).

실서비스 코드에서도 모델 종류 전환 때 Worker를 폐기하고 새로 만들어 두 모델의 동시 상주를 피한다. 이 추가 메모리 방어와 시험기 중계 수정은 서로 다른 조치다. CLIP 실제 응답을 확인했지만, 2회 정지 사진 시험이 연속 촬영·저사양 휴대폰 안정성을 보장하지 않는다.

## 위치 판정

공개 매물 이미지 `public/assets/cars/deutsch-autoworld-v01/p/0000.webp`~`0016.webp` 17장. 원본 / 0.42배 축소 / 2배 확대 / 0.7배+좌우 20% 이동 / 상하 약 46% 이동의 7조건, 총 119장. 같은 실내 촬영 장소·비슷한 구도의 사진으로 구성된 제한적인 세트다. 기존 보고서의 17장과 같다고 확인되지 않았다. 새로운 장소·야외·야간·반사·트럭·연속 카메라 움직임에 일반화할 수 없다.

| 조건 | 기대 안내 일치 | 나머지 |
|---|---:|---|
| 원본 | 16/17 위치 좋음 | 1장 앞으로 |
| 원거리 축소 | 16/17 앞으로 | 1장 판단 보류 |

상하 경계를 보지 않던 기존 판정식을 같은 최종 탐지 상자에 적용하면 위쪽 잘림 15장·아래쪽 잘림 7장을 `위치 좋음`으로 안내한다. 수정 판정식은 이 22장의 거짓 성공을 제거한다. 이는 동일 탐지 결과 위에서 판정식만 비교한 수치이며 전체 모델의 전후 정확도 비교가 아니다.

224px 전처리 시험은 원거리에서 8/17, 확대에서 9/17만 의도한 안내를 보여 채택하지 않았다. 최종 설정은 해상도와 탐지 점수를 조정하고 중복 탐지 상자를 분리한 뒤 재검증했다. 아래쪽에 차 일부만 보이면 검출 자체가 없는 경우가 여전히 많다. 이 경우 “차 전체가 틀 안에 보이도록 맞춰 주세요”로 돌아가며 성공으로 표시하지 않는다. 다른 차량보다 큰 배경 차량을 선택할 수 있는 위험도 남는다.

## 병합 전 남은 조건

1. Android Chrome(중급·저사양 포함)과 iPhone Safari에서 권한·세로/가로 회전·연속 촬영·앨범·저장/복원·백그라운드 복귀를 실제 기기로 확인.
2. 각각 AI 끔/켬 10분 이상 같은 장면·같은 밝기로 비교. 기기/OS, 카메라 해상도/FPS, 최초·재진입 준비 시간, 추론 P50/P95, 최대 RAM, 배터리 감소, 온도/스로틀링, 페이지 재시작을 기록. 지금 통과한 것으로 표시하지 않는다.
3. 캐시 없는 실제 통신망과 오프라인/느린 다운로드에서 셔터와 원본 저장이 계속 가능한지 확인.
4. 야외·야간·다중 차량·트럭 및 아래쪽 잘림을 포함하는 별도 표본에서 탐지 누락/거짓 성공을 검증. 잘림 안내가 필수 품질 요건이면 현 모델만으로 병합하지 않는다.

현재는 위 조건이 충족되지 않아 PR은 Open으로 유지하고 병합하지 않는다.
