# PR #352 모바일 피드 사진 영역 스크롤 버벅임 완화

① 피드에서 아래로 스크롤할 때 버벅이고 꼬인다는 제보에 대해, 원인 후보인 사진 넘기기 영역의 부담을 줄였다. 실제 기기 원인은 아직 확정하지 못했다.

② 과제 ID 미지정 · 브랜치 `fix/qf-m-feed-scroll-1010` · 커밋 4abdc7f · PR https://github.com/bobaekimboae/bobaedream/pull/352 · 상태 푸시(병합·배포 전) · 함께 들어간 과제 없음

③ 한 일
- 첫 사진만 먼저 그리고, 나머지 사진은 카드가 화면 근처(위아래 120px)에 오면 붙인다. 처음 화면에 올라가는 이미지가 75장에서 23장으로 줄었다.
- 사진 가로 영역이 세로 스크롤을 건드리지 않게 `overflow-y: hidden`, 그리기 범위 격리(`contain: layout paint`)를 넣었다.
- 한 장씩 강제로 멈추는 설정(`scroll-snap-stop: always`)을 뺐다. 현재 장 번호는 프레임당 한 번만 갱신한다.
- 비교용으로 주소 끝 `&feedphotos=single`을 붙이면 사진 1장짜리(넘기기 없음)가 된다.

④ 원본과 비교: 해당 없음(성능 작업). 화면 모양은 그대로다.

⑤ 검증
- `npm run verify:qf` 통과 · 콘솔 오류 모바일 0건 · PC 0건 · measure:qf 규격 변화 없음(차종 시트 대기 시간초과 1건은 main에서도 같음)
- 터치 스와이프 1→2→3장, 점·개수 갱신, 점 4px 유지 확인
- 데스크톱 헤드리스(CPU 4배 느리게) 세로 스크롤: 프레임 중앙 16.7ms, 50ms 넘는 프레임 0. 수정 전도 같아 **이 환경에서는 버벅임이 재현되지 않았다.**

⑥ 원본과 다르게 남긴 것: 없음.

⑦ 못 한 것·다음에 할 것
- 실제 기기에서 버벅임이 줄었는지 확인 필요. 그래도 남으면 `&feedphotos=single`과 비교해 사진 넘기기 영역 탓인지 가린다.
- 그래도 남으면 다음 후보: 카드 그림 영역 분리(`content-visibility`), 큰 사진 축소본 사용.

⑧ 확인 링크: 모바일 `?qf=guazi&view=feed` (비교: `&feedphotos=single`)
