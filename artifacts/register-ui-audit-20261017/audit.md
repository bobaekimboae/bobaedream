# GitHub Pages 등록폼 UI 전수조사

- 조사일: 2026-10-17
- 우리 배포본: https://bobaekimboae.github.io/bobaedream/?register
- 비교 기준: Chợ Tốt 로그인 자동차 등록폼 (`/dang-tin?category_group=3&ia_version=3`)
- 모바일 실측 폭: 393px(실제 CSS viewport 394px)
- 조사 범위: 진입 흐름, 정보구조, 반응형 레이아웃, 입력 컴포넌트, 미디어, 검증 상태, 고정 CTA, 타이포·색상·간격, 접근성, 실제 동작 여부

## 결론

### 구현 반영 결과

아래 초기 감사에서 발견한 P0·P1 차이를 반영해 GitHub Pages 매물등록 화면을 재구성했다. 초톳과 같은 섹션 순서, 모바일 2열 상세 필드, 86px 미디어 타일, 45px 입력 필드, 선택 칩, 3분할 고정 하단 액션을 적용했다. 이미지 첨부·삭제·재정렬, 서류 첨부, 미리보기, 임시저장, 등록 검증은 자동화 검증을 통과했다. 보배드림 브랜드와 한국어 매물 항목은 유지했다.

초기 감사 당시 배포본은 초톳 등록폼의 데이터 항목 일부를 참고한 별도 보배드림 목업에 가깝다. 화면 구조와 동작을 초톳과 동일하다고 볼 수 없다. 가장 큰 차이는 `차량번호 조회 전단계`, `폼 섹션 순서`, `모바일 단일열`, `미디어 모달`, `하단 단일 CTA`다.

모바일 상세폼 전체 높이는 우리 2,887px, 초톳 1,936px로 우리 쪽이 951px(약 49%) 더 길다. 초톳은 상세 필드를 158×45px 2열로 배치하지만 우리는 대부분 322×56~57px 단일열로 배치한다.

## 발견한 차이 전체 목록

### P0 — 구조·핵심 동작

1. 우리만 차량번호 조회/정책 동의 전단계가 있다.
2. 상세 진입이 하드코딩된 목업 번호에 의존한다.
3. 초톳의 최상단 미디어 우선 구조가 없다.
4. 초톳의 `사진/영상 → 설명 → 제목 → 가격 → 주소 → 판매자 → 상세정보` 순서와 우리 `차량정보 → 사진/영상 → 판매정보 → 상세설명 → 성능기록부 → 부가서비스` 순서가 완전히 다르다.
5. 초톳 모바일 상세정보는 2열, 우리는 단일열이다.
6. 우리 모바일 전체 스크롤이 초톳보다 약 49% 길다.
7. 초톳 하단의 `미리보기 / 임시저장 / 등록` 3개 고정 액션 중 미리보기와 임시저장이 모바일에서 빠진다.
8. 우리 등록·임시저장·업로드는 실제 요청을 보내지 않는 목업이다. 등록하기는 성공 시에도 안내 토스트만 띄운다.

### P1 — 컴포넌트·상태

9. 초톳 사진 업로더는 본문 안에서 추가, 표지 지정, 삭제, 길게 눌러 순서 변경을 제공한다. 우리는 별도 모달의 고정 슬롯 방식이다.
10. 초톳 사진 타일은 약 86×86px, 우리 빠른 추가 버튼은 75×75px이다.
11. 초톳은 사진과 영상을 한 업로더에 합치지만 우리는 사진·영상·외부영상을 3개 진입점으로 나눈다.
12. 초톳 설명은 1,500자이며 상단 334×253px 입력이다. 우리는 2,000자이며 하단 322×292px 입력이다.
13. 초톳은 설명에서 제목을 생성한 상태를 보여준다. 우리는 제목을 별도 수동 입력으로 둔다.
14. 초톳 필드는 약 45px 높이, 12px 라운드, 카드 안 2열이다. 우리 모바일 차량 필드는 56px 높이의 구분선 행이며 라운드·외곽선이 사라진다.
15. 초톳 상세 필드 폭은 약 158px, 우리 모바일 주요 필드는 322px다.
16. 초톳 선택값에는 지우기(X) 아이콘이 있다. 우리는 대부분 우측 화살표만 있다.
17. 초톳은 필수/선택 항목을 구분한다. 우리는 색상·시트색상·압류·저당·보증·수입구분 등 요구 항목이 훨씬 많아 작성 부담이 다르다.
18. 초톳의 차량서류 업로드와 게시물 표시 토글이 없다.
19. 초톳의 판매자 유형 `개인/반전문` 선택 위치와 의미가 없다. 우리 `판매구분 일반/리스/렌트`는 다른 개념이다.
20. 초톳의 소유자 수·부속품·검사 유효 여부가 한 카드 안에 압축돼 있다. 우리는 압류·저당·보증·수입·매매유형을 길게 늘어놓는다.
21. 초톳 가격 오류는 최소 5,000,000 조건까지 설명한다. 우리는 빈 값 여부만 안내한다.
22. 초톳 선택 칩은 32px 높이, 완전 알약형, 선택 검정/미선택 연회색이다. 우리 일부 칩은 40px·5~8px 라운드로 규칙이 섞인다.
23. 우리 모바일 고정 헤더와 고정 푸터가 전체 페이지 캡처에서 콘텐츠 위에 중첩된다. 하단 안전영역과 섹션 종료 여백을 실제 기기에서 다시 검증해야 한다.

### P2 — 시각 디자인

24. 초톳 핵심 CTA는 `#FFD400` 노랑+검정 텍스트다. 우리 배포 모바일 CTA는 `#2E4159` 계열 파랑+흰색이다.
25. 초톳 모바일 본문 기본 크기는 14px 중심, 우리 폼은 15~16px 중심이라 행 밀도가 낮다.
26. 초톳은 12px/14px 라벨과 14px 값으로 계층이 분명하다. 우리는 모바일 차량 행 라벨 12.6px/700, 값 15px/300으로 굵기 대비가 과하다.
27. 초톳은 연회색 페이지 위 흰 카드와 12px 라운드를 일관되게 쓴다. 우리 첫 차량정보 카드는 내부 행이 평면 리스트처럼 보여 카드형 언어가 약하다.
28. 초톳은 카드 외곽 12~16px, 내부 16px 간격이 반복된다. 우리는 섹션마다 12/20/28/32px이 섞여 리듬이 불규칙하다.
29. 초톳은 상단 전역 헤더·검색을 유지한다. 우리 모바일은 `매물 등록` 전용 헤더로 교체되어 서비스 맥락이 달라진다.
30. 우리 PC는 보배 전역 GNB가 크게 차지하고 상세 카드가 592px로 고립돼 있다. 모바일 동일화와 PC 정보밀도 원칙이 분리되지 않았다.

## 접근성 위험

1. 접근성 트리에서 차량번호·제조사·모델 등 여러 텍스트박스가 이름 없는 `textbox`로 노출된다. `label[for]`와 고유 `id` 연결을 전부 점검해야 한다.
2. 색상·시트색상처럼 입력처럼 보이지만 모달을 여는 컨트롤은 텍스트박스 역할과 버튼 역할이 혼재한다.
3. 모바일 차량정보 입력은 CSS에서 `:focus-within` 테두리를 0으로 덮어 키보드 포커스 위치를 알아보기 어렵다.
4. 뒤로가기 아이콘의 실제 버튼 영역이 24×24px로, 모바일 권장 44×44px보다 작다.
5. 13px 오류문구 `rgb(240,50,94)`와 일부 회색 보조문구는 작은 텍스트 대비를 재측정해야 한다.
6. 선택 칩 상태가 접근성 트리에서 단순 `generic`으로 보이는 항목이 있어 라디오/토글 상태 전달이 불명확하다.

## 권장 수정 순서

1. 초톳과 동일한 섹션 순서 및 모바일 2열 그리드로 정보구조를 먼저 교체한다.
2. 미디어 업로더를 본문 최상단의 통합형으로 바꾸고 표지·삭제·재정렬 상태를 넣는다.
3. 하단 고정바를 3버튼 체계로 바꾸고 안전영역·스크롤 가림을 수정한다.
4. 45px 필드, 12px 라운드, 14px 본문, 32px 칩으로 토큰을 통일한다.
5. 초톳에 없는 보배 전용 항목은 접기/고급정보로 이동해 기본 스크롤을 줄인다.
6. 라벨 연결, 역할, 포커스 표시, 터치 영역, 대비를 보정한다.
7. 실제 임시저장·미리보기·업로드·등록 연결은 UI 동일화 뒤 별도 기능 단계로 검증한다.
